# 结构化日志与可观测性

[卡片目录](README.md) · [第五阶段课程](../20-课程笔记/第五阶段-评估与部署课程及实践顺序.md)

## 一句话解释

**结构化日志把事件写成固定字段；可观测性让你从运行证据判断系统发生了什么。**像实验记录有时间、编号和结果，方便对照，而不是只有“出错了”。

## 本地服务记录哪些字段

每行一个 JSON：UTC 时间、request_id、路由类别、HTTP 状态、latency_ms、命中数量。通过同一个请求 ID 对照返回与日志，区分参数错误、索引过期、正常无命中。

默认不记录问题原文、笔记正文、请求头或密钥，也关闭 HTTP 处理器自带的原始 URL 日志。日志仍属于本地运行数据，保存到 `.local/`。第四阶段的完整消息记录含正文，两类记录的内容边界不同。

Python logging 文档提供日志设施与教程；本项目用标准库组织 JSON Lines，并非部署完整监控平台。[官方入口](https://docs.python.org/3.13/library/logging.html)

## 怎样利用它排错

先定位 request_id → 看路由和状态 → 判断是请求、索引还是程序问题 → 再在允许范围查看相关实验数据。不要为了方便把所有环境变量或 API 响应原样打印。

日志、指标和调用轨迹各有用途；当前没有报警、日志轮转或远程采集，长期运行时再按实际需求补充。
