# Tokenizer与聊天模板

[卡片目录](README.md) · [进阶课程](../20-课程笔记/进阶阶段-模型原理本地部署与微调.md)

## 一句话解释

**Tokenizer 把文字编码成 Token ID；聊天模板先把角色、正文和特殊标记排成模型学过的对话格式。**像先按表格规则写好问答，再把内容转换成机器能处理的编号。

## 为什么需要它

“把用户文字送进模型”中间还有格式转换。不同模型的词表、特殊标记和角色格式可能不同，自己拼一句 user: 并不一定等于该模型的聊天模板。

训练和推理若格式不兼容，模型可能重复问题、不知道何时开始回答，或把控制标记当正文。学习微调之前，先确认真正送入模型的序列。

## 用 MindVault 走一遍

以训练集中“一句话卡片”为例：user 要求把 Token 整理成固定格式，assistant 提供“概念：Token；一句话：……”示范。

下面只展示角色组织思路，不是真实 Qwen 特殊标记：

```text
[用户角色] 把 Token 整理成一句话卡片 [用户结束]
[助手角色] 概念：Token；一句话：模型处理文本的基本单位。 [回答结束]
```

推理时只提供问题并加上“助手开始回答”的提示；训练时要包含参考回答。`add_generation_prompt=True` 用来添加适用模板的回答起点，具体效果依赖模型模板。

假设模板后的问题是教学 ID [10,11,12]，完整对话是 [10,11,12,20,21]，本库会组织：

| 字段 | 教学值 | 作用 |
| --- | --- | --- |
| input_ids | [10,11,12,20,21] | 整段序列 |
| prompt_ids | [10,11,12] | 生成时提供的前缀 |
| labels | [-100,-100,-100,20,21] | 问题不计损失，回答位置计损失 |

这些 ID 是人为举例，不是实测分词。真实编码使用基座自己的 apply_chat_template；本库先检查完整对话的前缀是否与问题一致，避免错误地把回答也屏蔽。

## 每一步的输入输出

| 步骤 | 输入 | 输出 |
| --- | --- | --- |
| 整理消息 | user/assistant 角色和正文 | messages 列表 |
| 应用模板 | 模型兼容的模板 | 带角色与边界的序列 |
| 编码 | 模板内容与词表 | Token ID 列表 |
| 设置训练标签 | 前缀长度与完整序列 | 问题屏蔽、回答保留 |
| 解码输出 | 新生成 ID | 可阅读文字 |

在本例因果语言模型训练中，模型内部处理下一 Token 的标签移位；不要再手工移一次而错位。

## 常见疑问

**同一中文句子在所有模型中 Token 数相同吗？**不保证。词表、切分、特殊标记和模板都影响长度。

**-100 是真实 Token 吗？**不是，它是本训练损失约定里的忽略标签值，不放进 input_ids，也不是让模型生成 -100。

**屏蔽问题损失就等于模型看不到问题吗？**不是。问题仍在输入中供回答参考，只是不把问题位置当要评分的目标。

**能先套模板再随便加特殊 Token 吗？**可能重复。优先让官方模板直接 tokenize，若分开处理要确认是否已含所需标记。

**plan 通过就证明真实模板兼容吗？**没有。plan 不加载 Tokenizer；真实 train/evaluate 才编码和检查。

## 小练习与自测

**题目：**问题占三个 ID，完整对话五个 ID，把 labels 全设 -100 会怎样？

**参考答案：**没有有效回答目标，无法实现预期监督训练。应只屏蔽前缀，保留回答 Token。

**练习：**先写出一条样本的角色顺序，再指出推理输入与训练输入分别在哪里结束。准备真实环境后再查看真实 Token 结果。
