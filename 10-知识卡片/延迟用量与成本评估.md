# 延迟、用量与成本评估

[卡片目录](README.md) · [第五阶段课程](../20-课程笔记/第五阶段-评估与部署课程及实践顺序.md)

## 一句话解释

**延迟是等多久，用量是消耗多少，成本是按实际规则付多少；三者相关但不能互相代替。**像打车的等待时间、行驶里程与最终费用。

## 先分开计时

建库、检索、模型生成与整个任务分别测。使用单调计时器衡量耗时；时间戳用于对齐日志，不用系统时钟差值替代精确耗时。[Python perf_counter](https://docs.python.org/3.13/library/time.html#time.perf_counter)

项目报告给出少量检索样本的中位数和最近秩法 P95：把耗时升序排列，取第 `ceil(0.95×样本数)` 个。只有几题时它几乎是最大值，不能当生产负载性能结论。

## API 费用要看真实用量

第四阶段可能多次携带历史请求模型；请求轮数、字符数都不是 Token 用量。保存各轮实际 usage、模型和请求 ID，再按调用当天的价格核对账单。[DeepSeek 当前计费入口](https://api-docs.deepseek.com/quick_start/pricing/)

第五阶段默认离线检索和预写情节，API 请求数为 0，usage 写 null；这表示没有接口用量记录，不伪造成真实返回的“0 Token”。

## 小练习与自测

- [ ] 记录样本数、计时范围和机器环境，再讨论快慢。
- [ ] 真实调用后把每轮 usage 汇总，与服务账单核对。

**问题：**工具调用少了一次，就一定更便宜吗？

**参考要点：**不一定；输入输出长度、缓存、模型和其他费用也会变化。
