# 延迟、用量与成本评估

[卡片目录](README.md) · [第五阶段课程](../20-课程笔记/第五阶段-评估与部署课程及实践顺序.md)

## 一句话解释

**延迟是等多久，用量是消耗多少，成本是按实际规则付多少。**像打车的等待时间、里程和账单：彼此有关，不能拿一个直接代替另一个。

## 为什么需要它

学习助手也需要在可接受的时间和预算内工作。检索加快，不代表整个回答加快；请求次数减少，也不代表费用减少。

先写清计时范围、样本数、环境和模式，才能知道“20 毫秒”指检索、生成还是从提问到返回的全部过程。

## 用 MindVault 走一遍

`evaluate.py` 只计每题检索耗时，不含建索引、预写 Agent 检查、模型生成或网络。默认 dev 五道题，只有五个检索计时样本。

用虚构的五个耗时演算，单位毫秒，**不是本机实测**：`8、9、10、12、40`。

| 指标 | 怎么算 | 示例结果 |
| --- | --- | --- |
| 中位数 | 升序取中间值 | 10 毫秒 |
| 最近秩法 P95 | 第 ceil(0.95×5)=5 个 | 40 毫秒 |
| 样本数 | 被计时的检索次数 | 5 |

P95 关注较慢的尾部请求；只有五个样本时几乎就是最大值，不能据此宣布能承受生产流量。真实性能还受并发、机器、资料规模、冷启动和网络影响。

费用另算。假设某服务虚构单价是输入每百万 Token 2 元、输出每百万 Token 6 元，一次输入 1000、输出 200，费用为 `1000/1000000×2 + 200/1000000×6 = 0.0032 元`。仅为教学算术，不是任何厂商当前报价。多轮 Agent 要汇总每轮实际用量，考虑实际缓存及计费分类。

本阶段离线检索与预写情节 api_requests 为 0、usage 为 null，没有模型 API 请求。null 是没有这类用量记录，不是厂商返回“0 Token”。

## 每一步的输入输出

| 步骤 | 输入 | 输出 |
| --- | --- | --- |
| 定范围 | 检索、生成或全任务 | 明确计时边界 |
| 测耗时 | 单调计时器的起止值 | 毫秒样本 |
| 汇总 | 样本、排序方法 | 中位数、P95、样本数 |
| 收用量 | 各轮真实 usage | 按模型与计费分类的用量 |
| 核费用 | 用量、调用日价格与账单 | 费用及误差说明 |

perf_counter 用来测经过时间，UTC 时间戳用来对齐日志。电脑校时可能改变墙上时钟，不宜直接用它替代耗时计时器。

## 常见疑问

**字符数等于 Token 吗？**不等于。字符预算控制一种长度；实际用量看分词规则与接口返回。

**工具少调用一次一定便宜吗？**不一定。后续请求可能更长，模型可能不同，也可能有其他服务费。

**live 缺 usage 可以填零吗？**不能，应写未获得用量并核账单。离线零请求和真实请求缺记录不同。

**同样参数两次耗时不同算失败吗？**时间有波动。固定环境与范围、收集足够样本再比较，不要求毫秒数逐字复现。

**首字延迟与总延迟一样吗？**前者是多久开始收到流式输出，后者是多久完成。当前检索与非流式示例没有测这个分项。

## 小练习与自测

**题目：**二十个样本用最近秩法求 P95，取第几个？

**参考答案：**升序后第 `ceil(0.95×20)=19` 个，计数从 1 开始。

**练习：**读报告先说计时范围和样本数，再说快慢。没有真实调用时，费用写“未调用模型”，别猜账单。
