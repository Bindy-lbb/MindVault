# 上下文

[知识卡片目录](README.md) · [学习地图](../学习地图.md)

## 一句话解释

**上下文是模型生成这次回答时可以参考的材料；上下文窗口是这份材料与生成内容所受的容量限制，通常按 Token 表示。**具体计算规则随模型而异。[概念依据：Anthropic 上下文窗口文档](https://platform.claude.com/docs/en/build-with-claude/context-windows)

## 用生活里的事理解

可以把上下文想成你做题时摊在桌上的资料：题目、要求、参考页和已有草稿。桌面有多大，好比上下文窗口的容量。

资料存在书柜里，还需要取出来放到桌面，做题时才能参考。MindVault 的全部笔记也需要由应用读取并提供给模型。

## 一个具体例子

**自拟教学场景：**一份笔记写着：“本周只学习 Python 文件读取，暂时不做模型部署。”

把这句话与“请安排今天的学习任务”一起提供给模型，它就有了安排任务的相关依据。

如果没有把笔记或相关内容提供给模型，这条个人计划就不在本次输入材料里。

## 需要区分的三件事

| 概念 | 可以怎样理解 |
| --- | --- |
| 训练得到的知识 | 训练过程形成在模型参数中的规律和能力 |
| 本次上下文 | 这次实际提供的要求、消息、资料或工具结果 |
| 应用的记忆功能 | 应用另行保存并按需取回的信息；取回的内容可再提供给模型 |

提供资料和训练模型是不同的过程。[术语依据：Anthropic Context window 词汇表](https://platform.claude.com/docs/en/about-claude/glossary#context-window)

## 放到 MindVault 中有什么用

做笔记问答时，先找到相关笔记，再把需要的段落和问题一起提供给模型。后续学习 RAG，就是把“找资料再回答”的过程组织起来。

## 容易误解的地方

- 聊天界面显示的全部历史，不一定完整提供给每一次请求；应用可能进行摘要、截断或检索。
- 上下文容量大，不保证模型始终准确抓住每一处信息；相关、清楚的材料仍然重要。
- 提供资料时还要按模型规则为回答预留空间，不能把容量全部当作可输入的文章长度。[容量与管理依据](https://platform.claude.com/docs/en/build-with-claude/context-windows)

## 我的理解与验证

- [ ] 给模型一段自拟计划再问学习安排，检查回答是否使用了计划。
- [ ] 另开一次不包含该计划的请求，比较结果；在笔记中记录实际提供了哪些材料。
- [ ] 用自己的话解释：“我的笔记在电脑里，模型为什么还需要读取它？”

## 自测与参考答案

**问题：**笔记已经保存在 MindVault，是否说明模型这次回答一定能参考它？

**参考要点：**还要看应用是否读取并提供了相关内容。文件存在、应用能够访问、内容实际进入本次上下文，是需要区分的环节。
