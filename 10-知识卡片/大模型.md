# 大模型

[卡片目录](README.md) · [课程入口](../20-课程笔记/第一阶段-线上课程与阅读顺序.md)

## 一句话解释

**这里的大模型主要指大语言模型 LLM：通过训练形成大量数值参数，根据输入生成文字的模型。**它可以帮助解释、总结和写作。“大模型”也包括图像、语音等模型，本阶段先学文字任务。

## 为什么需要它

使用 AI 时，容易把模型、聊天软件、搜索和文件存储混成一件事。分清它们，才能理解为什么模型能写总结，却不会自动打开电脑里的所有笔记。

MindVault 的核心资料是 Markdown 文件；模型是帮助处理资料的一种能力。程序还需要读取文件、组织任务、调用接口、检查并保存结果。

## 用 MindVault 走一遍

项目 02 的示例文章《从记录到复习》说，学习新概念时先自己解释、举例，之后再回答问题，并核对 AI 笔记。

给模型的任务可以是：“根据正文写 1–3 句摘要，列出原文观点和逐字依据；额外建议单列。”模型根据这些要求和文字生成候选结果，我们再核对。

| 组成 | 在这个任务中做什么 |
| --- | --- |
| Markdown 文件 | 保存原始资料 |
| Python 程序 | 读取、发送、验证和保存 |
| 模型 | 生成摘要、观点等候选文字 |
| 服务 API | 按协议接收请求和返回结果 |
| Obsidian | 阅读和修改本地笔记 |
| GitHub | 保存提交的版本 |

模型生成可先理解为：输入被转成 Token，模型给后续 Token 打分，按生成规则逐步选出内容，直到结束。训练时学到的参数参与计算，普通回答过程通常不更新参数。

因此，即使回答看起来很专业，也可能遗漏、曲解或补造内容。模型输出是待检查的作品，不是它已经核实全部事实的证明。这里是应用场景说明，不是一次真实调用记录。

## 每一步的输入输出

| 步骤 | 输入 | 输出 |
| --- | --- | --- |
| 提供任务 | 原文、要求、格式 | 本次可用上下文 |
| 生成 | 上下文与已有模型参数 | 候选回答 |
| 检查 | 回答与原文 | 确认、修正或待核实项 |
| 保存 | 核对后的内容和来源 | 可阅读笔记 |

第一阶段先实现文件处理；第二阶段才把生成能力接入程序。

## 常见疑问

**模型是不是数据库？**它可以形成知识相关能力，但参数不是逐篇文章可查询的原文目录，需要原文依据时仍要提供或检索资料。

**发笔记就是训练吗？**普通聊天只是把资料放进这次输入；是否用于服务后续训练另看产品的数据政策，不能与这次参数更新混为一谈。

**参数更多一定更适合吗？**还要看任务表现、资源、速度和费用，规模不能代替同题评估。

**有大模型为什么还学 Python？**为了把文件、请求、结果检查和保存串成可重复流程，不是为了手工重写整个模型。

## 小练习与自测

**题目：**模型写了一份流畅摘要，是否已经证明摘要准确？

**参考答案：**还要逐项对照原文，检查重点、限定条件和新增信息。

**练习：**把“读文件、生成、保存版本”分别分配给程序、模型和 GitHub，再说明哪一步需要人工核对。
