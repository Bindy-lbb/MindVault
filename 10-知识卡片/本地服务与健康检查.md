# 本地服务与健康检查

[卡片目录](README.md) · [第五阶段课程](../20-课程笔记/第五阶段-评估与部署课程及实践顺序.md)

## 一句话解释

**本地服务是持续等请求的程序；健康检查分别确认它能响应，以及依赖是否足以完成任务。**像图书馆开门了，不代表书库和检索系统也能用。

进程是正在运行的程序；端口是应用接收连接的编号。127.0.0.1 是本机回环地址，8765 是本例端口。

## 为什么需要它

前面的命令行脚本执行一次就结束。服务启动后会继续等待，浏览器或另一个程序可以多次发请求，不必每问一题重新启动整个程序。

但“端口有响应”只证明部分功能。资料更新、索引过期时，程序可能还活着，却已无法可靠检索。因此需要存活检查、就绪检查和实际查询三种证据。

## 用 MindVault 走一遍

从项目配置建索引，再启动 local_service.py serve。保持该终端运行，在第二个终端发请求。具体完整命令见实践二，本页先看各请求意味着什么：

| 请求 | 问什么 | 正常返回 |
| --- | --- | --- |
| GET /health | 服务能响应吗 | 200、status=ok |
| GET /ready | 索引与资料仍匹配吗 | 200、status=ready、文档和块数 |
| GET /search?q=API...&k=3 | 找到哪些原文片段 | 200、hits、request_id |

GET 表示读取请求。q 是问题，k 是最多片段数，只允许 1–3。中文问题应先做 URL 编码，例如 PowerShell 的 `[uri]::EscapeDataString('API 密钥放在哪里？')`，再拼进请求。

搜索返回的是原文片段、来源、行号和分数，不是模型生成的完整回答，model_api_requests 为 0。

| 实验现象 | 状态码 | 应如何理解 |
| --- | --- | --- |
| 查询土星光环，hits 为空 | 200 | 搜索正常，无候选 |
| search 缺 q 或 k 超范围 | 400 | 请求参数不合要求 |
| 资料变了，ready/search 失败 | 503 | 索引不可用，需要核对重建 |
| 未定义的地址 | 404 | 没有这个接口 |

在实验副本修改资料后，health 仍可能是 200，而 ready/search 为 503。这不是互相矛盾：进程可响应，但资料版本不再就绪。停止，换新索引名重建，再启动核对。

## 每一步的输入输出

| 步骤 | 输入 | 输出 |
| --- | --- | --- |
| 建库 | 合法配置与资料 | 匹配版本的索引 |
| 启动 | 配置、索引、空闲端口 | 持续运行的本机进程 |
| 探测 | health 与 ready | 存活和就绪状态 |
| 实际查询 | 编码后的问题和 k | 原文片段或明确错误 |
| 停止与重启 | Ctrl+C，再运行 serve | 新进程复用有效索引 |

启动时先检查索引。缺索引时可能直接启动失败，此时并不存在一个可访问的 health；“health 仍成功”指启动后依赖发生变化的实验。

## 常见疑问

**这是不是部署大模型？**这是部署检索应用，不加载大模型权重。模型问答仍走项目 03/04 的显式调用。

**关终端后还在运行吗？**正常前台运行随终端关闭而停止。当前没设置开机启动或自动重启。

**能直接提供给其他人使用吗？**当前只监听本机且无认证、HTTPS 和生产运行管理。Python 官方不建议把 http.server 直接用于生产；远程服务要另选架构。

**health 失败就一定要重建索引吗？**先分清进程未启动、端口错误、端口被占或连接失败。索引重建只解决资料与索引问题，不解决所有连接问题。

## 小练习与自测

**题目：**200 空 hits 与 503 有什么区别？

**参考答案：**前者搜索已执行但无候选；后者当前索引不可用，不能把系统故障当作“资料没有答案”。

**练习：**请求三个接口后，停止并重启，用同一问题复查。资料变化实验只改实验副本，保留状态与恢复证据。
