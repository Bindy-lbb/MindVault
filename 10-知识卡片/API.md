# API

[卡片目录](README.md) · [课程入口](../20-课程笔记/第一阶段-线上课程与阅读顺序.md)

## 一句话解释

**API 是软件提供给其他程序使用的一套能力接口和规则。**全称 Application Programming Interface，常译为应用程序编程接口。像菜单和点单规则，说明能做什么、怎么提交、会返回什么。

## 为什么需要它

聊天窗口由人直接操作；自己的程序要自动整理文章，就需要按接口规则使用模型服务。这样读取、调用、检查和保存才能重复执行。

API 不只属于 AI，也不一定联网：本地库、操作系统也提供接口。本阶段重点是网络模型 API，下一阶段再用相同输入输出思维理解工具。

## 用 MindVault 走一遍

文章整理的四步是：程序读取正文 → 向模型 API 提交整理要求 → 接收响应 → 验证并保存 Markdown 草稿。

| API 文档项目 | 需要回答的问题 | 本库例子 |
| --- | --- | --- |
| 入口 | 请求发到哪里 | /chat/completions |
| 方法 | 怎样提交 | POST |
| 认证 | 如何证明调用权限 | API Key 请求头 |
| 请求数据 | 提供哪些字段 | model、messages 等 |
| 返回数据 | 从哪里取回答 | choices 中的 message.content |
| 错误 | 失败怎么识别 | HTTP 状态、结构及结束原因 |

DeepSeek 是项目 02 的具体教学接口，规则不能无条件套到其他服务。读懂这些部件，比死记某个完整命令更方便迁移。

“API 请求成功”只表示某层处理成功。还要看回答是否正常结束、内容是否符合格式、依据是否支持观点。返回 200 不是文章事实正确的证书。

Python 程序使用 POST 调模型，和 Git push 提交笔记到 GitHub 是两个独立流程。调用模型后，草稿先落到本地，核对后才进入正式知识库版本。

## 每一步的输入输出

| 步骤 | 输入 | 输出 |
| --- | --- | --- |
| 准备 | 正文、任务、接口设置 | 请求体 |
| 认证提交 | 地址、请求头、请求体 | 服务处理或错误 |
| 读取响应 | 状态与返回 JSON | 回答和元信息 |
| 校验 | 内容与规则、原文 | 接受或拒绝 |
| 保存 | 待核对结果 | 本地草稿文件 |

API 定义交换规则，客户端代码负责真正执行网络请求和文件操作。

## 常见疑问

**有 API Key 就自动有调用程序吗？**Key 是凭据，仍需客户端组织请求。

**装 SDK 等于有账户吗？**不是。SDK 是软件包，服务账户和权限是另一层。

**API 可以免费用吗？**按具体服务与账户条件确认。本库 preview/mock 没有真实模型请求，live 可能收费。

**请求把所有笔记都发走吗？**当前 summarize 发送所选正文和规则，不自动扫描全库；仍应先在 preview 核对实际输入。

**网络 API 和本地函数有什么共同点？**都有约定输入、输出与错误，只是执行位置和通信方式不同。
