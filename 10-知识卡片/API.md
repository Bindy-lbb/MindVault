# API

[知识卡片目录](README.md) · [学习地图](../学习地图.md)

## 一句话解释

**API 是软件提供给其他程序使用的一套接口和规则。程序按约定提出请求，就能使用对方的某项能力。**全称是 Application Programming Interface，中文常译为“应用程序编程接口”。[概念依据：MDN API 词汇表](https://developer.mozilla.org/en-US/docs/Glossary/API)

## 用生活里的事理解

把一个服务想成餐厅。菜单说明能点什么、需要哪些信息；你按要求下单，餐厅返回结果。

在这个类比里，API 文档像点单说明：程序需要按约定提供输入，再接收返回内容。

## 一个具体例子

**自拟的 MindVault 应用流程：**

1. 我的程序读取一篇文章正文。
2. 程序通过模型服务的 API 发送正文和整理要求。
3. 模型服务返回生成内容，或返回错误。
4. 程序检查结果，把合适的内容保存为 Markdown 草稿。

读取文件、调用模型、保存文件各有自己的步骤。API 把调用过程连接起来，模型负责其中的生成任务。

## 初次看 API 文档关注什么

| 项目 | 要回答的问题 |
| --- | --- |
| 能力和地址 | 能调用什么，向哪里发送请求？ |
| 认证 | 是否需要 API Key 等凭据？ |
| 输入 | 要提供哪些字段，格式是什么？ |
| 输出和错误 | 结果怎样读取，失败如何识别？ |

不同 API 的规则不同，按目标服务的文档逐项确认。

## 容易误解的地方

- API 不只用于 AI，也可以用于地图、文件或其他软件功能。
- API 不一定是联网服务；软件库和操作系统也有 API。[范围依据：MDN](https://developer.mozilla.org/en-US/docs/Glossary/API)
- API Key 是某些服务用于认证的凭据；文本 [Token](Token.md) 则是模型处理内容的单位。
- 请求成功只说明服务按接口完成了处理，生成内容仍需检查 [幻觉](幻觉.md)。
