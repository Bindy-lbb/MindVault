# LoRA与QLoRA

[卡片目录](README.md) · [进阶课程](../20-课程笔记/进阶阶段-模型原理本地部署与微调.md)

## 一句话解释

**LoRA 冻结原有基座，学习两个小矩阵构成的低秩更新；QLoRA 把量化基座与 LoRA 适配训练结合。**像保留原书，另加一组专门批注，但数学上是对权重变换加入增量。

## 为什么需要它

全参数更新需要为很多权重计算和保存训练状态。LoRA 主要训练较少参数，便于保存与切换任务适配；基座仍要加载和计算，并非不占资源。

低秩是结构约束，不是更好质量的保证。是否足以表达任务变化、是否提升答案，都需要看数据和评估。

## 用 MindVault 走一遍

常见记法是 `W = W0 + (alpha/r)BA`。按列向量约定，W0 为 d_out×d_in，A 为 r×d_in，B 为 d_out×r。

假设一个 4096×4096 的权重，原有 16777216 个数；rank r=8 时，A/B 合计 `8×4096+4096×8=65536` 个数，是该矩阵元素数的 1/256。这只算选中矩阵，不是整个模型内存压缩比。

本库玩具模型 W0 是 2×2 单位矩阵，A 形状 1×2，B 是 2×1，alpha=r=1。取理想 A=[1,2]、B=[1,2] 列向量，BA=[[1,2],[2,4]]，加上 W0 得 [[2,2],[2,5]]，输入 [2,1] 后输出 [6,9]。

这个目标恰好能被 rank1 增量表达。2×2 例子里 A/B 共有四个数，恰好与原矩阵元素数相同，不能拿它证明节省参数；它只是便于手算。大矩阵示例才展示 r 较小时的数量差异。

| 方式 | 基座表示 | 更新什么 | 本库状态 |
| --- | --- | --- | --- |
| 玩具 LoRA | 单位矩阵 | 自写 A/B | 可离线真实计算 |
| 真实 LoRA 选修 | FP32 基座 | q_proj/v_proj 的适配参数 | 需另准备环境运行 |
| QLoRA | 常见为冻结 4-bit 基座 | 较高精度的低秩适配参数 | 当前未实现 |

原始 QLoRA 还包含 NF4、双重量化和分页优化器等内存设计，不能把“任何量化文件加两个矩阵”都当作本库已实现的 QLoRA。

## 每一步的输入输出

| 步骤 | 输入 | 输出 |
| --- | --- | --- |
| 选择目标层 | 基座架构和任务 | 要加入 LoRA 的层 |
| 初始化 | 固定基座、rank 和缩放 | 可训练 A/B |
| 前向 | 基座输出与增量输出 | 适配预测 |
| 训练 | 数据、损失和梯度 | 更新后的 A/B，基座不变 |
| 保存重载 | 适配参数和兼容基座 | 可验证的适配行为 |

本例 A 为随机小值、B 为零。初始增量为零；若 A、B 都为零，这个双线性更新的两侧梯度都会被另一侧的零堵住。

## 常见疑问

**rank 越大越好吗？**增加表达能力也增加训练参数与资源，可能过拟合。按验证结果选择。

**alpha 是参数数量吗？**不是，是增量缩放相关超参数；常见缩放为 alpha/r，具体变体要看实现。

**冻结基座就不需要基座文件吗？**仍需要，它负责原有映射。适配器不是完整模型。

**当前真实脚本是 QLoRA 吗？**不是。它使用 FP32，没有量化配置。

**玩具 adapter.json 能加载到 PEFT 吗？**不能，文件格式、基座和维度都不同。

## 小练习与自测

**题目：**W0 是 100×200，rank=4，A/B 有多少个参数？

**参考答案：**A 是 4×200，B 是 100×4，共 800+400=1200；原矩阵 20000 个数，未计其他层与开销。

**练习：**实践二训练后保存再重载，输入 [2,1]，比较基座 [2,1]、适配结果与目标 [6,9]。解释为什么这个例子容易拟合。
