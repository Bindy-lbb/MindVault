# Token

[卡片目录](README.md) · [课程入口](../20-课程笔记/第一阶段-线上课程与阅读顺序.md)

## 一句话解释

**Token 是模型处理文字的小单位，Tokenizer 按特定规则把文本变成这些单位的编号。**它不固定等于一个字、一个词或一个标点；可以像装箱时按规则拆分的不同大小小块。

## 为什么需要它

模型的输入容量、输出上限和很多 API 费用都与 Token 有关。如果把字符数当成 Token 数，容易误判文章能否装下、回答会不会截断以及费用多少。

先学会分清计数口径，再使用目标模型的分词或返回统计确认。

## 用 MindVault 走一遍

项目 01 会计算 `len(content)`，它是读取后的 Python 字符串长度。比如 `len("AI学习")` 为 4；这不是在调用分词器，也不能据此说用了四个 Token。

模型输入除了文章，还包括整理要求、消息角色的模板等信息。修改“只总结”变成“总结、列依据并提问题”，通常会改变实际输入，不能只按正文字符数估算整次调用。

| 计数 | 数什么 | 能否直接当 Token |
| --- | --- | --- |
| 文件字节 | 编码后的存储量 | 不能 |
| Python 字符串长度 | 文本中的字符单位，含换行等 | 不能 |
| Token 数 | 目标分词规则下的单位 | 要确认模型与统计范围 |
| API usage | 服务报告的实际处理统计 | 按字段与计费规则解释 |

假设某次服务报告输入 300、输出 80 Token，总计 380。这是虚构统计示例，不是“300 字文章”的换算，也不是本次实际调用。多轮历史若再次送入，也需要再次处理，不是只计算新增一句话。

API 的访问凭据有时也叫 token，那是认证术语；这里的文本 Token 是另一件事。

## 每一步的输入输出

| 步骤 | 输入 | 输出 |
| --- | --- | --- |
| 组织请求 | 要求、正文和消息 | 完整任务输入 |
| 分词/编码 | 输入与目标模型规则 | Token ID 序列 |
| 生成 | 已有序列 | 新 Token |
| 统计 | 本次真实请求 | 输入/输出等实际用量 |
| 核对 | 模型与统计口径 | 容量和费用记录 |

文本怎样切分依模型不同，本页不编造某个中文短语的真实 Token ID。

## 常见疑问

**两个一千字文章 Token 一样吗？**不保证，内容、语言和分词规则会影响数量。

**输出上限 1200 就一定生成 1200 吗？**它是限制，不是固定用量；回答可能提前结束。

**中文一定一字一个 Token 吗？**不能固定这样算，组合字词、符号和编码都有差异。

**mock 的 usage=null 表示什么？**没有真实模型用量。不能把它改成猜测值作为实测。

**本地字符限制是 Token 限制吗？**项目 02 的 20000 字符正文限制只是教学输入约束，不是模型上下文窗口。

## 小练习与自测

**题目：**`len("AI学习")=4`，能推出模型输入正好四个 Token 吗？

**参考答案：**不能，这只统计 Python 字符串；模型还会按自身规则编码，也可能有额外模板。

**练习：**先记录一段文本字符数，真实调用条件具备后再保存 usage，注明模型和日期，不用固定比例倒推。
