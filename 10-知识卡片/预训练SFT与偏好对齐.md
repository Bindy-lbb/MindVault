# 预训练SFT与偏好对齐

[卡片目录](README.md) · [进阶课程](../20-课程笔记/进阶阶段-模型原理本地部署与微调.md)

## 一句话解释

**预训练从大量数据学习广泛规律；SFT 用示范输入输出学习任务行为；偏好对齐利用哪些回答更合适的反馈进一步调整行为。**像先广泛阅读，再看标准示范，再比较不同解法的优劣，但这只是类比。

## 为什么需要它

下载到的聊天模型通常已经经历过多种训练。自己用少量示例做 LoRA，是在已有能力上适配，不是重新创造所有知识。

先区分训练目标与更新方法，能避免把“使用 LoRA”与“做 SFT”当成互斥选项：SFT 描述学什么、根据什么示范学；LoRA 描述主要更新哪些参数。

## 用 MindVault 走一遍

假设希望模型稳定输出“概念：…；一句话：…”。

| 阶段 | 可能使用的数据 | 要学什么 |
| --- | --- | --- |
| 预训练 | 大量文本序列 | 基于上下文预测后续内容等基础规律 |
| SFT | 用户要求与合格示范回答 | 按任务组织输出 |
| 偏好对齐 | 同题更偏好/不偏好的回答或其他反馈 | 更符合所定义偏好的行为 |

本库 SFT 示范是“把 Token 整理成一句话卡片”与标准格式答案。训练时提高参考回答 Token 的概率，不是在每一步让评委打分。

若比较两个答案：A 格式正确且解释准确，B 格式正确却把 Token 说成固定一个汉字，可以将 A 设为偏好、B 为不偏好。但偏好标签也要核对事实与任务，不能只因为 A 更长就判更好。这是数据形态示意，本库没有偏好数据训练。

RLHF 常利用偏好反馈建立奖励信号并通过强化学习等方法优化；DPO 是直接利用偏好对的另一类方法，不应把所有偏好训练都说成同一流程。当前不需要先掌握算法公式，也不运行这些方法。

流程可以迭代或采用不同组合，不是所有模型都严格只有固定三段。SFT 也不只用于聊天；这里为降低学习成本，只做单轮对话格式适配。

## 每一步的输入输出

| 步骤 | 输入 | 输出 |
| --- | --- | --- |
| 定义目标 | 通用能力、任务格式或偏好问题 | 适合的训练目标 |
| 准备监督 | 文本、示范或偏好反馈 | 相应数据格式 |
| 选择更新方式 | 全参数或参数高效方法 | 可训练参数与配置 |
| 训练 | 数据、损失和优化器 | 新权重或适配器 |
| 独立验证 | 保留题和人工规则 | 收益、退步和限制 |

训练可能同时影响知识、风格和其他能力，不能把这些阶段理解成只改一个互不影响的开关。

## 常见疑问

**二十条卡片示例足够重新预训练吗？**不是。它们只用于演示小规模适配流程，甚至未必改善已有模型。

**偏好对齐能保证事实正确吗？**不能。效果依赖数据、规则和评估，偏好本身也可能不等于真实性。

**SFT 是把全部笔记背下来吗？**训练可能记住内容，但当前目标是格式与任务行为。不断更新、需要引用的笔记通常先用 RAG。

**LoRA 属于哪一阶段？**它是参数更新方法，可用于某些 SFT 或其他训练目标，本项目用于监督微调选修。

**本项目预训练过模型吗？**没有，也没有运行 DPO、奖励模型或强化学习。小矩阵训练与真实语言模型训练另行记录。

## 小练习与自测

**题目：**“用 LoRA 做 SFT”矛盾吗？

**参考答案：**不矛盾。前者描述低秩参数更新，后者描述以示范输入输出为监督。

**练习：**为格式任务写一条好示范，再写一对偏好答案，指出它们训练监督有什么不同；只做数据设计，不先启动训练。

- [ ] 用自己的话解释，并写下尚未验证的部分。
