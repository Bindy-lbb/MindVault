# 训练与推理

[卡片目录](README.md) · [课程入口](../20-课程笔记/第一阶段-线上课程与阅读顺序.md)

## 一句话解释

**训练通过数据反馈调整模型参数；推理使用已有参数处理当前输入并给出结果。**像先通过练习形成解题方法，再用已有方法解一道新题，这只是帮助理解的类比。

## 为什么需要它

把笔记交给模型、改变提示词和训练模型是不同操作。分清它们，才能判断是否需要准备训练数据、计算资源和独立评估，也能理解为什么一次聊天不会自动把知识库永久写进权重。

当前学习路线先做应用：读取、调用、核对。进阶阶段才按需接触参数训练。

## 用 MindVault 走一遍

项目 02 读取《从记录到复习》，要求生成摘要。live 使用已经训练好的服务模型生成文字，这是推理；本地程序不对模型执行梯度更新。

如果后来准备多组“输入概念 → 合格的一句话卡片”示范，并实际用训练程序更新指定参数，才属于适配训练。仅保存示范 JSON 还没开始训练。

| 操作 | 改变什么 | 是否属于本地模型训练 |
| --- | --- | --- |
| 改提示为三句话 | 本次任务输入 | 否 |
| 把正文附在请求中 | 本次上下文 | 否 |
| 保存 API 返回为 Markdown | 磁盘文件 | 否 |
| 运行更新权重的训练循环 | 指定可训练参数 | 是 |
| 运行 mock 固定响应 | 本地处理流程 | 连真实推理也没有 |

训练可先理解为：预测、与参考目标比较、计算损失、求梯度、更新参数。推理通常不走更新步骤，变化的是输入与输出。

推理请求是否会被服务商留存、用于后续改进，是产品的数据使用政策问题；不能从“本次没有更新权重”直接推出“服务不会保存任何内容”。这两种含义需要分别确认。

## 每一步的输入输出

| 过程 | 输入 | 主要输出 |
| --- | --- | --- |
| 训练准备 | 数据、目标、基座和设置 | 可执行训练方案 |
| 训练更新 | 示例与损失反馈 | 新参数或适配器 |
| 训练评估 | 独立问题和评分规则 | 收益与退步 |
| 普通推理 | 已有模型和本次任务 | 回答或错误 |
| 应用保存 | 输出及核对结论 | 草稿或正式笔记 |

模型训练好与应用能稳定运行是不同验收项，后续评估与部署会分别处理。

## 常见疑问

**我不断纠正聊天回答，就是微调吗？**通常是把反馈加到当前上下文；有没有训练要看是否存在参数更新流程。

**给模型一本书就学会所有内容了吗？**当前请求可能参考材料，但不保证逐项准确，也不意味着永久记忆。

**微调一定让通用能力更强吗？**不保证，可能只适配格式，也可能过拟合或退步，需要独立测试。

**推理只发生一次计算吗？**自回归回答常逐 Token 计算，API 一次请求可以包含许多生成步。

**第一阶段需要训练模型吗？**不需要，先完成文件读取与数据保存。

## 小练习与自测

**题目：**将 API 响应保存为笔记，能写“我训练了模型”吗？

**参考答案：**不能，只完成了调用或模拟及文件保存。要明确实际执行模式。

**练习：**把提示修改、正文上传、参数更新、Git 提交四项分别放到任务输入、训练和存储流程中，并解释依据。
