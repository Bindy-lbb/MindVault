# 工具错误与恢复

[卡片目录](README.md) · [第四阶段课程](../20-课程笔记/第四阶段-工具调用与Agent课程及实践顺序.md)

## 一句话解释

**恢复是读懂失败原因后，改变参数、换方法或结束任务。**它不是把同一个请求原样再做十遍。像借书失败，先区分书名写错、没有这本书，还是借阅系统坏了。

## 为什么需要它

工具是程序，也会遇到非法输入、资料变化和网络故障。不给模型明确反馈，它可能以为已经读到了内容，继续编出题目。

错误最好让调用方能采取行动：比如“top_k 必须是整数”比“失败了”更有用。程序还要判断哪些错误可以继续，哪些应该立即结束；这部分不能完全交给模型决定。

## 用 MindVault 走一遍

本库 `bad_arguments` 的第一条搜索请求把 top_k 写成 `"3"`。结果返回 invalid_arguments；下一轮预写响应改为整数 3，搜索才成功，再读取原文并输出题目。它演示的是协议层面的恢复路线，不证明真实模型一定会修正。

| 情况 | 返回或停止标签 | 合理下一步 |
| --- | --- | --- |
| 搜索没命中 | ok=true、data=[] | 改关键词，或承认依据不足 |
| 类型、字段、行号错误 | invalid_arguments | 依据错误修正具体字段 |
| ID 不在清单 | unknown_note | 使用允许清单内的 ID，不扩大目录 |
| 工具未登记 | unknown_tool | 使用已有工具或结束 |
| 运行中资料变化 | corpus_changed | 当前循环立即停止，新快照重开 |
| 请求超时等异常 | request_error | 当前循环停止，人工定位 |
| 响应结构不合约定 | invalid_response | 停止并检查接口或响应 |
| 最终 JSON 或引文不合法 | invalid_final | 停止并核对内容 |

空结果不是程序崩溃。`no_results` 情节会成功执行一次搜索，但找不到“土星光环倾角”，随后返回 insufficient_evidence。诚实说明缺资料比编题更合适。

恢复要改变导致失败的条件。行号超过末尾时缩小行范围；JSON 无法解析时修格式；资料版本变化时重新启动。对 unknown_tool 反复提交同一个不存在的工具名不会获得新能力。

## 每一步的输入输出

| 步骤 | 输入 | 输出 |
| --- | --- | --- |
| 执行 | 工具名与参数 | 成功数据或带 code/message 的错误 |
| 分类 | 错误码与当前预算 | 可调整、无依据或必须停止 |
| 回传 | 普通工具错误 | 对应 ID 的 tool 消息 |
| 修正 | 反馈与任务 | 新参数或明确结束 |
| 留痕 | 所有尝试 | 失败与恢复过程一起保留 |

本库遇到 corpus_changed 会在本地立即停止，不等待模型自行决定是否使用旧原文。

## 常见疑问

**自动重试不是更方便吗？**临时网络错误有时适合有限重试，但类型错误需要改参数；盲目重试只增加耗时。本项目 API 请求失败后不自动重试。

**以后有写入工具，超时后直接再写一次行吗？**先确认前一次有没有实际完成。请求超时可能只是回执没收到；重复创建会产生两份内容。可设计幂等键：同一动作使用同一编号，服务端识别后只完成一次。当前只读示例没有实现这类写入机制。

**工具失败一定是模型错吗？**不是，也可能是资料被改、网络异常或程序实现问题。先看失败发生在哪一层，再决定修改对象。

## 小练习与自测

**题目：**搜索返回空数组，应该记录“API 不可用”吗？

**参考答案：**不应该。搜索本身成功，只是当前关键词没有命中。它与请求失败属于不同层次。

**题目：**行号错误被修复后，第一次失败是否从统计中删掉？

**参考答案：**保留。它消耗了工具尝试，也反映真实恢复成本；只展示最后一次成功会掩盖问题。
