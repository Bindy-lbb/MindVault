# 超时、限流与重试

[知识卡片目录](README.md) · [第二阶段课程](../20-课程笔记/第二阶段-模型API课程与实践顺序.md)

## 一句话解释

**超时表示客户端没能在等待限制内完成相应网络操作；限流表示请求触及服务限制；重试是再次发送请求。**先辨认原因，再决定下一步。

## 用生活里的事理解

像窗口办事：材料缺失应补材料，队伍拥挤可以稍后再来，等不到答复则先确认状态；处理方式各不相同。

## 本项目关注的状态

| 情况 | 学习时怎样处理 |
| --- | --- |
| 400 / 422 | 检查请求格式、字段和参数 |
| 401 | 检查认证配置 |
| 402 | 检查账户余额与使用计划 |
| 429 | 检查请求频率、并发限制，降低调用速度 |
| 500 / 503 | 服务端问题，稍后再尝试并记录 |
| 网络超时 | 确认网络和服务状态，再决定是否重发 |

这些映射以 [DeepSeek 错误码](https://api-docs.deepseek.com/zh-cn/quick_start/error_codes/)为例。不同服务需要各自核实。

## 本项目为什么不自动重试

一次调用失败时，脚本只返回清楚提示。特别是客户端等待超时，并不能据此确认服务端完全没处理请求；重复发送可能产生额外处理与费用。

后续需要自动重试时，再学习次数上限、等待间隔和退避策略。Python 的网络 `timeout` 是网络操作的等待设置，不应当理解为所有处理步骤的严格总时长保证。[网络行为参考](https://docs.python.org/zh-cn/3.13/library/urllib.request.html)

## 自测与参考答案

**问题：**401 错误时，立即连续请求十次通常能解决吗？

**参考要点：**应先检查认证配置。重发相同的错误认证通常不能解决原因。
