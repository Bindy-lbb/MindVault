# 参数

[知识卡片目录](README.md) · [学习地图](../学习地图.md)

## 一句话解释

**模型参数是模型内部通过训练学到的数值，例如权重和偏置，它们参与模型的计算。**[定义依据：Google parameter 词条](https://developers.google.com/machine-learning/glossary#parameter)

## 用生活里的事理解

把模型想成一台内部有很多旋钮的机器。训练通过数据反馈调整这些旋钮；使用训练好的模型时，按当前配置处理输入。

“旋钮”只是类比。实际参数是数值，不是可以逐个打开阅读的知识卡片。

## 一个具体例子

**自拟教学场景：**在模型说明中看到“7B parameters”。如果这里的 B 使用十亿这个常见计数单位，7B 就表示约 70 亿个参数。

这个数字表示参数规模，不能直接换算为“读过多少篇文章”或“能回答多少个问题”。

## “模型参数”和“调用参数”要分清

| 名称 | 指什么 | 平时怎样接触 |
| --- | --- | --- |
| 模型参数 | 内部权重、偏置等学到的数值 | 在模型规模和训练说明里看到 |
| API 请求参数 | 请求中填写的字段，如模型名称、消息或输出限制 | 调用接口时按服务文档设置 |

第二行是接口用语。“修改一个请求参数”这个操作，本身不等于训练模型或改动权重。普通 [提示词](提示词.md) 修改也不会调整权重。[提示词边界依据：Google](https://developers.google.com/machine-learning/crash-course/llm/tuning#prompt-engineering)

## 放到 MindVault 中有什么用

以后记录模型选型时，把“用了哪个模型”和“请求里设置了什么”分别写清楚。比较实际的文章整理效果，比单看参数数量更能回答当前项目是否适用。

## 容易误解的地方

- 参数数量不能直接当成模型效果、速度或内存需求的完整说明。
- 参数不是文章目录，不能按编号拿出某一篇原文。
- 把一篇笔记发给模型，通常是在补充 [上下文](上下文.md)；是否进行了训练，要看有没有参数更新过程。

## 我的理解与验证

- [ ] 找一份模型说明，记录模型名称、参数规模及原始来源。
- [ ] 用自己的话说明“模型有多少参数”和“API 传了哪些参数”的区别。
- [ ] 到模型调用阶段，把一次请求的设置写进项目记录。

## 自测与参考答案

**问题：**我把提示词从“写详细一点”改成“只写三句话”，模型的参数数量增加了吗？

**参考要点：**没有。这里调整了任务输入与表达要求，普通提示操作不会增加、删除或修改模型权重。
