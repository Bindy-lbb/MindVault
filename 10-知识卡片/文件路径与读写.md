# 文件路径与读写

[卡片目录](README.md) · [课程入口](../20-课程笔记/第一阶段-线上课程与阅读顺序.md)

## 一句话解释

**路径说明文件在哪里，读取把磁盘内容变成程序数据，写入把处理结果保存到磁盘。**像地址、取出资料和另存成果三个步骤，不是只看到文件名就已经打开了文件。

## 为什么需要它

第一阶段要读 Markdown，第二阶段要发送实际正文并保存草稿。路径错误、编码不匹配和输出覆盖，都是与模型无关却经常发生的问题。

先确定当前目录、输入位置和新输出名，再执行，能避免把问题误归为模型或 API 故障。

## 用 MindVault 走一遍

从 MindVault 根目录运行下面的只读 Python 示例：

```python
from pathlib import Path

source = Path("30-项目实践/01-Markdown读取小程序/examples/示例笔记.md")
content = source.read_text(encoding="utf-8-sig")
print(source.name)
print(source.suffix)
print(len(content))
```

source.name 是示例笔记.md，suffix 是 .md。len 是读取后字符串长度，包含换行，不是文件字节或 Token 数。

| 路径写法 | 意义 | 本库例子 |
| --- | --- | --- |
| 绝对路径 | 带完整位置 | E:/my-projects/MindVault/... |
| 相对路径 | 从某个起点寻找 | 10-知识卡片/Token.md |
| 脚本所在位置 | 程序文件自身目录 | 默认示例通过 __file__ 定位 |
| 当前工作目录 | 终端或进程的起点 | 命令里传入相对路径通常从这里算 |

项目 01 默认示例按脚本目录定位；自己传入相对路径时按当前工作目录解析。换终端目录后同一短路径可能不再指向原文件，所以实践文档先让你进入仓库根目录。

读取使用 utf-8-sig，兼容开头有 BOM 的 UTF-8 文本。保存 JSON 用 UTF-8 和新建模式 x，已有输出会报 FileExistsError。普通 w 模式可能截断已有文件，不能随便替换当前保护规则。

## 每一步的输入输出

| 步骤 | 输入 | 输出 |
| --- | --- | --- |
| 定位 | 当前目录与路径 | 目标文件位置 |
| 读取 | 文件和编码 | str 正文 |
| 处理 | 原文 | 标题、字段等数据 |
| 选新输出 | 新文件名与后缀 | 不覆盖输入的位置 |
| 写入再读回 | 数据与编码 | 可验证的保存结果 |

Path 只是路径对象；建立它本身不会创建或读取文件，read_text/open 等操作才执行 I/O。

## 常见疑问

**Obsidian 里看得到，Python 就一定找得到吗？**还要检查真正磁盘位置和工作目录，应用显示名不自动变成程序路径。

**Markdown 读取后就去掉格式了吗？**当前按普通文本读，#、链接和 YAML 都可能保留；不是完整渲染或解析器。

**为什么有时中文乱码？**可能是文件编码或终端显示编码不一致，先分清读取失败与显示异常。

**输出相同文件名能重复跑吗？**当前拒绝覆盖，改新名即可。不要为了省事去掉保护。

**写到 .local 后 Obsidian 找不到怎么办？**隐藏目录通常不在文件树显示，可在复盘记录路径，正式核对后的笔记再保存到可见目录。

## 小练习与自测

**参考答案：**当前项目不是，用户相对路径按工作目录；默认示例另用脚本位置定位。

**练习：**读示例后另存新 JSON，再读回标题；故意用不存在路径和已有输出名，分别记录失败提示。
