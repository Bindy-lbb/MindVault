# 评估集与数据划分

[卡片目录](README.md) · [第五阶段课程](../20-课程笔记/第五阶段-评估与部署课程及实践顺序.md)

## 一句话解释

**评估集是一组固定问题及其判断依据；数据划分让调试题和最后检查效果的题分开使用。**像练习册和模拟考试：练习题用来找问题，留出的题帮助检查方法能否应付新问法。

这里评估的是应用，不要求重新训练模型。对于 MindVault，问题可以是“API 密钥放哪里”，判断依据是对应笔记和支持结论的原句。

## 为什么需要它

凭几次聊天感觉“不错”，很难知道改动是否真的有效。固定题目后，改检索参数、提示词或模型，才能看到同一道题发生了什么变化。

题集也需要贴近用途：原词问题考基本检索，改写问题考换个说法，多来源题考材料完整性，资料外问题考系统能否承认信息不足。大量重复的简单题不能代替这些覆盖。

## 用 MindVault 走一遍

第五阶段自带八道教学题：dev 有四道有依据题和一道资料外题；holdout 有两道有依据题和一道资料不足题。默认只跑 dev。每题格式如下，取自本库题集：

```json
{
  "id": "dev-api",
  "split": "dev",
  "question": "API 密钥放在环境变量中吗？",
  "expected": [{
    "path": "01-API配置.md",
    "quote": "API 密钥用于认证调用方，建议放在本地环境变量中。"
  }]
}
```

`id` 是唯一题号；`split` 是所属分组；`question` 是实际输入；`expected` 说明需要哪些来源和原句。path 相对选定的资料目录，不是相对题集文件。多来源题有多个 expected 条目；资料外题是空数组。

标签的意思是“根据当前选定资料，这题需要这些依据”，不代表世界上只有这一种表达。脚本会确认原句存在于目标文件，却不会自动判断标签是否合理。把真实句子误标给无关问题仍可能通过存在检查，需要人工修正。

dev 用于反复定位问题；holdout 留到方案相对稳定后检查。如果反复看 holdout 失败并照着调参数，它就逐渐成了另一组调试题。当前题目公开、数量很少，只演示流程，不能称为独立的大规模用户测试。

## 每一步的输入输出

| 步骤 | 输入 | 输出 |
| --- | --- | --- |
| 选用途 | 真实学习任务和允许资料 | 需要覆盖的问题类型 |
| 写题与标注 | 问题、目标文件、原句 | 可核对的题目条目 |
| 划分 | 分组与使用规则 | dev 和保留的 holdout |
| 检查标签 | 当前资料版本 | 来源、原句存在或报错 |
| 运行与保存 | 固定题集、参数 | 逐题结果与汇总报告 |

只改几个词但答案和来源完全相同的题，如果分散到两组，独立性仍很弱。真实项目可按文档、主题或时间分组，减少同类内容跨组泄漏。

## 常见疑问

**这里的 dev、holdout 是模型训练集吗？**本项目用它们检查检索应用，没有训练过程。以后微调时还会涉及训练、验证和测试数据，需要另外设计划分。

**没有唯一标准答案也能评吗？**可以先标来源、原句、必须满足的条件和应拒答的情况。开放题不必逐字相同，但判断规则应明确。

**资料更新后还用旧题吗？**可以保留问题，但要重新核对标签。报告保存题集、资料和代码摘要，条件改变应在对比时说明。

**资料外题等于搜索不到吗？**不等于。问题可能含 Token 等相关词，搜到片段却没有账户余额等所需信息。候选相关性和答案充分性是两回事。

## 小练习与自测

**题目：**模型自动写了二十道题和答案，能直接当评估标准吗？

**参考答案：**先人工核对。题目可能重复、答案可能错误，引用可能不支持结论。自动生成适合做草稿。

**纸上练习：**选一题原词、一题改写、一题资料外。写出来源与原句；资料外题写清当前资料缺少什么，而不是随便留空。

### 动手记录

- [ ] 给自己的笔记补 3 个问题，人工标出依据。
- [ ] 留至少一个没用来调参的改写问题，最后再跑。
