# RAG 评估与故障定位

[第三阶段阅读顺序](../20-课程笔记/第三阶段-RAG课程与实践顺序.md) · [项目 03](../30-项目实践/03-RAG知识库问答/README.md)

## 一句话解释

**RAG 评估要分别检查“有没有找对依据”和“有没有根据依据答对”。**故障定位则是顺着数据流找出出错的一步，避免一看到错误就换模型或乱改参数。

## 为什么需要它

一次回答正确，可能只是问题太简单；一组问题结果变好，也可能只是换了资料。没有固定问题和明确评分标准，就很难知道改动究竟有没有用。

先准备一些你知道答案在哪里的问题，写下目标文件和支持结论的原句，再运行系统比较。这份带预期的题目集合就是评估集。还要放入资料外问题，观察系统会不会硬找依据或乱答。

## 用 MindVault 走一遍

对“API 密钥应该放在哪里，能写进 Git 吗？”先标注：目标文件是 `01-API配置.md`，关键依据是其中的存储建议和禁止提交句子。

如果结果含这个文件但只取出了“真实请求可能收费”，虽然文件对了，段落仍不够。即使正确两句都到了模型上下文，模型也可能漏答“能否提交 Git”。因此可以逐层检查：文件 → 片段 → 最终上下文 → 回答 → 引用。

## 每一步的输入输出

| 步骤 | 输入 | 输出 |
| --- | --- | --- |
| 人工标注 | 问题和原始资料 | 预期文件、原句及回答要求 |
| 固定配置 | 资料版本、切分、检索方法、K | 可复现的实验条件 |
| 运行检索 | 同一题集 | 候选顺序及来源 |
| 运行生成，可选 | 检索材料和问题 | 答案、引用、耗时与用量 |
| 分层评分 | 预期与实际结果 | 检索指标、答案问题和失败类型 |
| 单变量改进 | 一个失败原因 | 新结果与前后对照 |

## 两个检索指标，手算一次

本项目先使用“来源文件级”指标。假设有三个确定有答案的问题，取 K=3：

| 问题 | 目标文件首次出现名次 | 是否命中 | 名次倒数 |
| --- | --- | --- | --- |
| Q1 | 1 | 是 | 1 |
| Q2 | 3 | 是 | 1/3 |
| Q3 | 前三条未出现 | 否 | 0 |

**Hit@3**：三题中两题至少命中一个目标文件，得到 `2/3 ≈ 66.7%`。

**MRR@3**：把每题首次命中的名次取倒数，没有命中记 0，再平均，得到 `(1 + 1/3 + 0)/3 ≈ 0.4444`。它让靠前命中的题得到更高贡献。

这张三题表是教学演算，不是本库实际测得的成绩。若一道题需要两份资料，来源级 Hit 只找到其中一份也可能算命中，所以仍要检查证据是否完整。无答案题单独记录返回候选的情况，不放入这两个指标的有答案题分母。

## 回答质量怎样检查

至少检查三点：是否回答了用户的问题；是否忠于给定材料；引用是否支持每个关键结论。可以人工为每题写“通过、部分通过、失败”和理由，再逐步制定一致的评分表。

同时记录速度、真实服务返回的 Token 用量，以及失败情况。离线摘录没有模型 Token 实测值；不能用它推断真实生成的成本和正确率。

## 按症状找到下一步

| 现象 | 优先检查 | 一个可验证的动作 |
| --- | --- | --- |
| 文件根本没入库 | 资料目录、格式、清单 | 在 manifest 中查路径 |
| 条件和结论分开了 | 切分与重叠 | 查看对应片段的起止行 |
| 正确片段排名靠后 | 表达、检索方法、K | 固定资料，只比较 K=1 与 K=3 |
| 片段对了但请求里没有 | 上下文组织与预算 | 检查 preview 的真实材料 |
| 材料对了但回答错 | 漏条件、模型解释、引用 | 对照原句逐项批注 |
| 总出现旧内容 | 索引、资料版本、缓存 | 先确认查询使用哪个快照 |

## 常见疑问

**Hit@3 达到 100% 就完成了吗？** 它只说明这组有答案题至少命中过目标文件。题目可能过于简单，片段可能不完整，也没有检查生成答案。

**一次同时换切分、模型和 K 可以吗？** 可以做探索，但难以判断改进来自哪里。初学先一次改一个变量，保留同一题集和资料快照。

**能让模型给自己打分吗？** 可以辅助，但评分模型也可能出错。先建立人工可核对的参考，再抽查自动评分；当前检索评估脚本不做模型裁判。

## 小练习与自测

把表中 Q2 的名次从 3 改成 1，其他不变，Hit 和 MRR 怎样变化？

参考答案：Hit 仍是 2/3，因为命中题数没变；MRR 变成 `(1+1+0)/3 = 2/3`，体现正确来源提前了。两者都没有测量生成答案质量。

## 本库实现与实践入口

项目自带 5 道有答案题、1 道资料外题，只是便于上手的小题集。`evaluate` 计算来源级 Hit@K、MRR@K，并记录每题结果，不调用生成模型。

按[实践二](../30-项目实践/03-RAG知识库问答/实践二-带引用问答与评估.md)比较两组配置，再用[评估记录模板](../30-项目实践/03-RAG知识库问答/评估记录模板.md)补充自己的同义改写、跨笔记问题和资料外问题。不要把小样例成绩外推到整个 MindVault。
