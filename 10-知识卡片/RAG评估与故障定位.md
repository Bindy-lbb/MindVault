# RAG 评估与故障定位

[知识卡片目录](README.md) · [第三阶段课程](../20-课程笔记/第三阶段-RAG课程与实践顺序.md)

## 一句话解释

**先检查是否找到了依据，再检查是否用对了依据。**像做饭先确认食材拿对，再检查烹饪方法，才能知道该改哪一步。

## 本项目的两个检索指标

给每个有答案问题手工标记目标来源文件：

- **来源级 Hit@K：**前 K 个片段中出现至少一个目标文件的问题数 / 有答案问题数。
- **来源级 MRR@K：**目标文件第一次出现的名次取倒数，没出现计 0，再对有答案问题求平均。第 2 名贡献 1/2。

目标文件命中仍可能拿错段落，所以这只是粗粒度的起点。无答案题单独记录是否仍返回候选，不混入上述分母。不要把“有返回结果”当成答案正确率。

LlamaIndex 的评估指南区分检索与回答，并介绍检索排名指标；本库采用手写问题和目标来源，避免把自动生成题直接当真值。[依据](https://developers.llamaindex.ai/python/framework/module_guides/evaluating/)

## 按症状排查

| 现象 | 先检查 |
| --- | --- |
| 文件根本没进索引 | 资料目录、格式、文件清单 |
| 关键句被拆断 | 切分大小、重叠、标题信息 |
| 目标片段排名靠后 | 问题表达、检索方法、K、重排序 |
| 片段正确但回答错误 | 提示词、遗漏条件、模型与引用 |
| 总回答旧内容 | 资料版本、索引更新、缓存 |

**参考要点：**不能；样本可能简单，来源命中不代表段落充分，更未检查生成答案。
