# 本地模型与推理服务

[卡片目录](README.md) · [进阶课程](../20-课程笔记/进阶阶段-模型原理本地部署与微调.md)

## 一句话解释

**本地模型是在自己设备保存权重并执行计算；推理服务把计算能力提供成可请求的接口。**像一本放在自己桌上的书与一个供程序查阅的窗口，是两层东西。

## 为什么需要它

第五阶段只把检索脚本作为服务运行，没有加载语言模型。本分支进一步让本机模型真正生成文字，也让你看到模型文件、服务进程、客户端请求各自负责什么。

本地运行使用本机内存、磁盘与计算时间，不自动等于所有数据都留本机。工具可能支持云模型，需要核对所选模型和后端配置。

## 用 MindVault 走一遍

本库用 Ollama 作为选修推理后端，客户端固定连接 127.0.0.1:11434，教学模型名为 qwen2.5:0.5b。它不是自动安装器：先自己确认设备和磁盘，再安装后端、下载所选模型。

| 模式 | 做什么 | 能证明什么 |
| --- | --- | --- |
| preview | 显示 tags 检查地址和 chat 请求 | 请求如何组织 |
| fixture | 解析固定教学响应并保存 | 结果处理逻辑可演示 |
| live | 检查模型清单后请求本机服务 | 实际模型运行结果，需记录 |

preview 不联网请求；fixture 没有模型推理，不填生成速度。live 先 GET /api/tags，确认有指定模型并拒绝带已识别远程标记的条目，再 POST /api/chat。

请求携带 messages、stream=false 和生成选项。返回要完成且模型名符合预期，客户端才接受有效 assistant 内容。假设真实响应 eval_count=40、eval_duration=2000000000 纳秒，解码吞吐约 `40/(2秒)=20 Token/秒`。这是计算示例，不是本机速度；加载时间和整个请求耗时另记。

Ollama 支持云功能，访问回环地址本身不能证明后端没有外部计算。需要纯本地时，按官方 FAQ 的本地模式设置、重启后核对；客户端的检查也不等于对所有网络行为的完整审计。

## 每一步的输入输出

| 步骤 | 输入 | 输出 |
| --- | --- | --- |
| 准备后端 | 设备、软件、所选本地模型 | 可用服务与模型文件 |
| 预览 | 问题与生成选项 | 将提交的请求 |
| 预检 | 模型清单 | 指定模型存在且符合本例条件 |
| 调用 | chat 请求 | 文字和实际计数/耗时 |
| 核对 | 模型 digest、回答、资源记录 | 可回看的真实实验 |

模型 digest 是内容标识，标签名可能随分发更新；记录标识有助于之后对照。

## 常见疑问

**没有显卡就一定不能运行吗？**不一定，取决于后端、模型和资源，但 CPU 可能较慢。不能仅凭参数量保证可用。

**GitHub 私有仓库是否已经运行模型？**没有。仓库存文件，Obsidian 读笔记，推理进程执行计算，职责不同。

**本地就不会幻觉吗？**不会因此消除幻觉。继续用同题评估、资料依据和人工核对。

**服务没启动与模型没下载一样吗？**不同。连接失败先查进程和地址；模型清单没有标签先查下载和名称。客户端不会遇错自动拉模型。

**HF 与 Ollama 的同系列名字可以混用吗？**分发格式和加载方式不同，不直接互换缓存、适配器或文件。

## 小练习与自测

**题目：**fixture 保存成功，能写“本机每秒生成 20 Token”吗？

**参考答案：**不能。它没有运行模型，也没有真实 Token 计数；示例算术不等于实测。

**练习：**先 preview，再 fixture。准备实际环境后检查 ollama list/ps，用不含私人资料的问题做 live，记录模型和输出。
