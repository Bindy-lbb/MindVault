# 应用配置与密钥管理

[卡片目录](README.md) · [第五阶段课程](../20-课程笔记/第五阶段-评估与部署课程及实践顺序.md)

## 一句话解释

**配置决定应用怎样运行，密钥证明调用权限。**资料在哪、端口多少可以写配置里；真实 API Key 应通过单独的本地或平台凭据机制提供。

配置像操作说明，密钥像门禁凭证，用途和保存方式不同。

## 为什么需要它

把路径端口写死在代码里，换环境难以检查。把密钥写进配置和 Git，又容易在历史、发布包与复制中传播。

本阶段先学没有密钥的检索服务。以后接模型时，继续把配置与凭据分开，避免为了启动就把 Key 粘进脚本。

## 用 MindVault 走一遍

service.example.json 的六个字段如下：

```json
{
  "corpus": "../03-RAG知识库问答/examples/notes",
  "index": ".local/service/index-v1.json",
  "log": ".local/service/events.jsonl",
  "port": 8765,
  "chunk_lines": 8,
  "overlap_lines": 2
}
```

| 字段 | 意思 | 注意点 |
| --- | --- | --- |
| corpus | 允许用于检索的资料目录 | 默认第三阶段五篇示例 |
| index | 索引文件 | .json，新建拒绝覆盖 |
| log | 日志文件 | 独立的 .jsonl |
| port | 本机服务端口 | 默认 8765，0 用于自动分配测试端口 |
| chunk_lines | 每块最多几行 | 1–100 |
| overlap_lines | 相邻块重叠行数 | 大于等于 0，小于块行数 |

**相对路径起点是配置文件所在目录。**所以 index 在项目 05 内部 .local/service，不是仓库根目录同名目录。终端换目录不会改变含义，但把配置文件复制到别处，路径起点会改变。

发布包的 service.json 把 corpus 改为 notes，指发布包内部 notes，不再访问原仓库。

当前服务不读取 API Key。项目 02/03/04 的真实模型请求才使用相应环境变量。不要为练检索先申请账户，或给这个 JSON 添加 Key；解析器只接受六个约定字段。

## 每一步的输入输出

| 步骤 | 输入 | 输出 |
| --- | --- | --- |
| 读取 | JSON 文件 | 六个约定字段 |
| 解析路径 | 配置位置与相对路径 | 绝对资料、索引、日志路径 |
| 校验 | 类型、后缀、数值关系 | 合法配置或错误 |
| 建索引 | 资料与切分参数 | 匹配配置的新索引 |
| 运行 | 配置和有效索引 | 本机服务 |

JSON 能解析不表示内容都有效；索引与资料一致性还要另查。

## 常见疑问

**改配置自动生效吗？**没有热更新。停止后用新配置重启；资料或切分改变时，用新索引名重建。

**旧索引能带去另一台电脑吗？**索引含资料绝对位置，移动后应在最终位置重建。不能只改一个路径字段假装版本一致。

**私有仓库可以存真实 Key 吗？**仍应分离。私有设置不能消除 Git 历史和后续复制带来的暴露。

**环境变量绝对保密吗？**不能保证。它减少源码里的凭据，但调试输出和进程环境的访问仍要控制，别把环境字典打进日志。

**端口被占用怎么办？**serve 可加 --port 8766，后续请求也换端口；不要随意终止不认识的进程。
