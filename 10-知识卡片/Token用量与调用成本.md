# Token 用量与调用成本

[卡片目录](README.md) · [课程入口](../20-课程笔记/第二阶段-模型API课程与实践顺序.md)

## 一句话解释

**用量是本次服务处理的 Token 统计，费用是按模型、计费分类和当时单价计算的金额。**像先称实际重量再按规则结算，不能把文章字数、输出上限和账单当同一件事。

## 为什么需要它

模型调用可能包含输入、输出和缓存等类别，多轮还会重复带入历史。知道成本来自哪里，才能把效果、长度和费用一起比较。

学习阶段更重要的是保留真实记录和计价单位，不把估算写成实测，也不把旧价格长期套在所有请求上。

## 用 MindVault 走一遍

下面是虚构 usage，用来理解字段，**不是这次请求的实际记录**：

```json
{"prompt_tokens":1000,"completion_tokens":200,"total_tokens":1200}
```

输入可能包含规则、正文和必要历史，不只文章；输出是生成内容。服务还可能返回缓存等明细，应按其当前含义解释。

假设教学单价输入每百万 Token 2 元、输出每百万 Token 6 元，没有其他分类，则这次费用是 `1000/1000000×2+200/1000000×6=0.0032 元`。这不是 DeepSeek 当前报价，实际须查调用日官方价格和账单。

| 要记录 | 为什么 |
| --- | --- |
| execution_mode | 区分 preview/mock/live |
| requested_model/response_model | 请求名与返回名可能不同 |
| request_id | 方便关联调用 |
| usage 原字段 | 保留实际输入、输出及明细 |
| 日期与计价单位 | 防止价格或单位误套 |
| 输出与失败 | 成本要与任务效果一起看 |

mock 的 usage=null，因为根本没有模型 API 请求。live 缺 usage 时只能写“未获得用量”，不能推为免费。请求成功也不等于账单已经核对完。

输出上限 1200 不等于每次输出 1200，也不是整个任务的费用上限；输入、重试和其他服务可能另有成本。

## 每一步的输入输出

| 步骤 | 输入 | 输出 |
| --- | --- | --- |
| 标明模式 | 实际执行路径 | 真实或模拟记录 |
| 收集返回 | usage 与模型、请求 ID | 本次用量证据 |
| 确认价格 | 日期、模型、分类和单位 | 适用单价 |
| 分项计算 | 各类用量×对应单价 | 估算金额 |
| 核账单和质量 | 账户记录与任务结果 | 完整成本结论 |

有缓存细分时不要把同一批输入既按总数计一次、又按细分计一次，避免重复求和。

## 常见疑问

**len(article) 能算费用吗？**只能提供字符规模线索，不是精确 Token 统计。

**少一次请求一定更便宜吗？**请求长度、模型、缓存和输出都可能不同，要比较真实用量与结果。

**模拟可以填预计数字吗？**可以在单独估算栏明确假设，不能改原 usage 冒充服务统计。

**花钱多就更正确吗？**不保证。用同题和人工标准判断收益，不只比较费用。

**用公开教程就所有练习免费吗？**资料阅读与模型服务费用不同，真实调用按自己的账户规则。

## 小练习与自测

**题目：**上述虚构单价下，输入 500、输出 100 Token 费用多少？

**参考答案：**`500/1000000×2+100/1000000×6=0.0016 元`，仍只是教学算术。

**练习：**先确认 mock 输出 usage=null；以后实际 live 再记录原字段、日期、单价来源及质量检查，保留估算与账单差异。

### 动手记录
