# Token 用量与调用成本

[知识卡片目录](README.md) · [第二阶段课程](../20-课程笔记/第二阶段-模型API课程与实践顺序.md)

## 一句话解释

**用量是这次请求实际处理的 Token 统计；费用需要结合对应模型和服务的当前计费规则计算。**DeepSeek 可以从响应的 `usage` 查看实际用量。[依据：Token 用量计算](https://api-docs.deepseek.com/zh-cn/quick_start/token_usage/)

## 用生活里的事理解

像寄件后看实际重量，再按适用价格结算。文章的字符数只能帮助观察输入规模，不能直接当作 Token 或金额。

## 实践记录什么

| 项目        | 用途             |
| --------- | -------------- |
| 调用模式      | 分清预览、离线模拟和真实请求 |
| 请求及返回模型名  | 方便复现与核对        |
| 输入与输出用量   | 观察资料和生成长度的影响   |
| 缓存等明细     | 有返回时按服务说明理解    |
| 计费日期与计价单位 | 防止把旧价格套进新请求    |
| 正确性与错误    | 成本要与实际任务效果一起比较 |

## 费用怎样估算

简化思路是各类用量乘以各类单价后相加；实际还要按服务文档确认缓存、时段和计价单位。本卡片不固定保存容易变化的单价，使用前打开 [模型与价格](https://api-docs.deepseek.com/zh-cn/quick_start/pricing/)核对。

## 容易误解的地方

- 输出上限不是实际用量，也不是总费用上限。
- 预览和模拟没有真实 API 用量，不能用编造数字冒充账单。
- 看见 `usage` 统计也不代表已经完成最终账单核对。

## 我的理解与验证

- [ ] 在模拟输出中确认 `usage` 为 `null`。
- [ ] 真实调用后保留返回的用量，并核对当前价格页。
- [ ] 用同一短文比较一次提示修改前后的结果与用量。

## 自测与参考答案

**问题：**离线模拟输出中没有实际用量，可以填入一个“预计消耗”当作实测吗？

**参考要点：**不能。估算与实测要分别标明，真实用量来自实际请求。
