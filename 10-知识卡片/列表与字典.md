# 列表与字典

[卡片目录](README.md) · [课程入口](../20-课程笔记/第一阶段-线上课程与阅读顺序.md)

## 一句话解释

**列表按顺序保存多项值，字典按键保存字段与对应值。**列表像一排笔记卡，字典像一张写有标题、状态和正文的信息表，二者可以嵌套。

## 为什么需要它

一篇文章有多个观点，一次对话有多条消息，单条消息又有角色与内容。理解列表套字典，才能看懂模型 API 的常见数据结构。

先学怎样取值、增加内容和处理缺字段，后续就不必把整份 JSON 当成神秘长字符串。

## 用 MindVault 走一遍

自写 Python 示例：

```python
notes = [
    {"title": "Token", "reviewed": False},
    {"title": "API", "reviewed": True},
]
print(notes[0]["title"])
notes.append({"title": "上下文", "reviewed": False})
notes[0]["reviewed"] = True
print(len(notes))
print(notes[0].get("source", "未提供"))
```

依次输出 Token、3、未提供。notes[0] 是第一张字典卡，接着 ["title"] 才是该卡标题。下标从 0 开始；两个元素的列表没有下标 2。

| 表达式 | 意义 |
| --- | --- |
| notes[0] | 第一项 |
| notes[-1] | 最后一项 |
| note["title"] | 按键取必需字段 |
| note.get("source", "未提供") | 缺字段时提供默认 |
| notes.append(new_note) | 在原列表末尾添加一项 |

字典没有某个键时，直接用方括号可能抛 KeyError；get 可表达可选字段，但也不能把真正缺失的必填项偷偷当正常。

第二阶段 messages 就是列表，每项是含 role、content 的字典。观点 key_points 也是列表，每项有 point 和 evidence。先从外往里一层层确认类型，再取值。

## 每一步的输入输出

| 步骤 | 输入 | 输出 |
| --- | --- | --- |
| 表示单篇 | 标题、状态等 | 字典 |
| 组织多篇 | 多个字典 | 列表 |
| 定位一项 | 列表与有效下标 | 单个字典 |
| 取字段 | 字典与键 | 标题等值 |
| 修改/遍历 | 数据与处理规则 | 更新的记录或显示结果 |

`copy = notes` 不会复制整个列表，只让另一个名字指向它。需要独立副本时再学习浅拷贝与深拷贝，别把同一份数据误当两份。

## 常见疑问

**列表和字典都用方括号取值，区别在哪？**列表按位置，字典按键；不能拿标题字符串当列表下标。

**len(notes) 是字符数吗？**这里是列表元素数，取决于对象类型。

**JSON 对象就是 Python dict 吗？**JSON 是文本格式，解析后常成为 dict；解析前还是字符串。

**字段次序决定意义吗？**按键访问才是重点，不应依赖把“第二个字段”当固定业务含义。

**append 会返回新列表吗？**它修改原列表，返回 None，不要把结果重新赋回 notes。
