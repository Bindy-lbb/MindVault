# 微调数据与评估隔离

[卡片目录](README.md) · [进阶课程](../20-课程笔记/进阶阶段-模型原理本地部署与微调.md)

## 一句话解释

**训练集用于更新参数，验证集帮助判断设置，测试集留到方案确定后检查。**像练习题、调试时的模拟题和最后验收题，要分清什么时候使用，避免把背过的题当作新能力。

## 为什么需要它

模型可能记住训练示范。训练题得分很高，不能证明对新问题也有效。测试题反复用于改参数后，也会逐渐参与方案选择，独立性变弱。

数据还应符合任务、内容正确且有权使用。把整座笔记库直接当示范，不仅可能格式不合，也可能混入互相矛盾的结论和不适合训练的私人内容。

## 用 MindVault 走一遍

本库只训练“概念：…；一句话：…”格式，二十条自写数据按 12/4/4 放在 train、validation、test 三个 JSONL。JSONL 是一行一个 JSON 对象，不是一个大数组。

下面是同类格式的教学示例：

```json
{"id":"example-01","messages":[{"role":"user","content":"把 Token 整理成一句话卡片。"},{"role":"assistant","content":"概念：Token；一句话：模型处理文本的基本单位。"}]}
```

| 分组 | 当前真实脚本怎么使用 | 不应用来做什么 |
| --- | --- | --- |
| train | 轮流取样、反向传播、更新 LoRA | 充当独立测试结果 |
| validation | 训练前后测平均回答损失 | 进入 optimizer 更新 |
| test | 独立 evaluate 模式比较基座与适配结果 | 每次失败就照题改训练方案 |

plan 会读取三组文件做结构检查，这不等于测试题已经进入模型训练；只有模型计算和参数更新的使用方式决定是否用于训练。

当前检查跨所有分组的重复 ID、空白归一化并忽略大小写后的相同问题。它不能识别“什么是 Token”和“请解释 Token”这类语义近似，也不能识别同一篇文章拆成不同片段的来源泄漏；这些需要人工和更适合的数据划分规则。

## 每一步的输入输出

| 步骤 | 输入 | 输出 |
| --- | --- | --- |
| 明确任务 | 目标格式和用户需求 | 合格示范标准 |
| 整理数据 | 有权使用且核对过的问答 | user/assistant 样本 |
| 按来源划分 | 文档、主题或时间 | 更独立的三组数据 |
| 自动与人工检查 | 字段、重复、语义与事实 | 通过项及待修正项 |
| 固定版本 | 三个文件的摘要 | 可对照的训练与评估记录 |

先分组再处理来自同一源的扩展样本，通常更容易防止同源变体跨组；具体策略仍要匹配任务。

## 常见疑问

**修改了测试数据还能直接比较旧 run 吗？**当前校验会拒绝数据摘要变化。应先说明实验条件变化，重新设计对照。

**完全不重复就算隔离了吗？**不够，同义改写、相同来源和相近目标都可能泄漏。当前小数据只演示流程，不证明广泛泛化。

**参考回答很短就一定好训练吗？**还要看是否准确、符合任务、覆盖必要条件。错误的简短答案仍会提供错误监督。

**公开能读就自动有训练使用权吗？**不能这样推断，需核对来源许可和使用条件；当前练习使用本库自写示范。

**训练后 loss 降了，能直接公布质量提升吗？**还要看独立题的实际输出、引用与人工评价，并保留退步样例。

## 小练习与自测

**题目：**把训练题只换一个词放测试，答得好能证明新任务能力吗？

**参考答案：**不能据此推断。它可能仍是近重复或同源内容，应检查语义和来源独立性。

**练习：**给一条示范做事实和格式核对，再写一条不同主题的保留题。先写评审标准，再决定是否修改数据版本。

### 动手记录

- [ ] 打开三个 JSONL，解释每组用途，补一条与训练主题不同的测试题。
- [ ] 用自己的话解释，并写下尚未验证的部分。
