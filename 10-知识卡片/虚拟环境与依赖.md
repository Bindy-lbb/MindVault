# 虚拟环境与依赖

[卡片目录](README.md) · [课程入口](../20-课程笔记/第一阶段-线上课程与阅读顺序.md)

## 一句话解释

**依赖是程序需要的软件包；虚拟环境为一个项目准备独立的 Python 包安装空间。**像不同实验各用一套工具，减少版本相互影响。

## 为什么需要它

一个项目要新版包，另一个还依赖旧版，混装容易出兼容问题。确认实际运行哪个 Python、包安装在哪，比只记“已经装过”更可靠。

第一、二阶段核心用标准库，不要求先装第三方包或 SDK。先把解释器与包的关系理解清楚，为后续选修准备。

## 用 MindVault 走一遍

常见名称先分清：

| 名称 | 作用 |
| --- | --- |
| Python 解释器 | 执行 .py 程序 |
| 标准库 | 随 Python 提供的模块，如 json、pathlib、urllib |
| 第三方包 | 另行安装的软件，如某些 SDK |
| pip | 安装和管理 Python 包的工具 |
| venv | 创建隔离环境的标准库模块 |
| .env | 常见配置文本文件，不是虚拟环境 |

先在 PowerShell 查看 `python --version`；用 `python -c "import sys; print(sys.executable)"` 查看当前解释器路径。不同终端可能选中不同解释器。

若后续确实需要独立环境，可从仓库根目录创建一个尚未使用的实验环境，例如 `python -m venv .local/python-basics-venv`。直接调用其中 Scripts/python.exe，就明确使用该环境；激活只是方便终端选到它，不是唯一使用方法。

安装包时用目标解释器的 `-m pip`，避免一个 Python 在运行、另一个 pip 在安装。此卡只说明方法，本次整理没有创建环境或安装包。

环境目录不放 Git：它可能含绝对路径和系统相关文件。保留版本和安装说明，换机器通常重新创建，而不是把整个 .venv 复制过去。

## 每一步的输入输出

| 步骤 | 输入 | 输出 |
| --- | --- | --- |
| 查看解释器 | 当前终端 | Python 路径和版本 |
| 确认需求 | 程序 import 与说明 | 标准库或第三方依赖 |
| 建独立环境 | 可用 Python、新路径 | 项目环境 |
| 安装并记录 | 目标解释器和明确包版本 | 可核对依赖 |
| 运行验证 | 同一解释器和脚本 | 环境是否可用 |

pip freeze 是当前已装包的快照，不能单凭它保证跨系统、跨设备完全一致。更严格复现留到第五阶段。

## 常见疑问

**装包后仍提示找不到怎么办？**先查运行解释器与安装解释器是否相同，再查包名和版本。

**激活环境后模型账号就有了吗？**没有，环境隔离与 API 账户认证不同。

**PowerShell 不允许激活脚本怎么办？**可直接调用环境里的 python.exe；不必为了当前练习更改整台机器策略。

**虚拟环境保护所有文件吗？**它主要隔离包，不是操作系统沙箱，也不自动限制程序读写和联网。

**环境变量就是虚拟环境吗？**不是。环境变量是进程配置；虚拟环境是解释器和包环境，可以在其中读取环境变量。

## 小练习与自测

**题目：**标准库 json 是否必须 pip install json 才能用？

**参考答案：**不需要，它随 Python 提供。先看文档和项目说明，别按模块名字盲装同名包。

**练习：**记录 sys.executable 与版本，再说明 .local、.venv 和 .env 各是什么。当前标准库项目先跑通即可。
