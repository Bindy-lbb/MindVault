# 虚拟环境与依赖

[知识卡片目录](README.md) · [学习地图](../学习地图.md)

## 一句话解释

**依赖是项目需要用到的软件包；虚拟环境为项目提供一套相对独立的 Python 和包环境，减少不同项目的版本冲突。**[参考：Python 虚拟环境和包](https://docs.python.org/zh-cn/3.13/tutorial/venv.html)

## 用生活里的事理解

不同项目有不同工具箱。把各自需要的工具分开放，更新一个项目的包时，就更容易避免影响另一个项目。

## 一个具体例子

在 MindVault 根目录的 PowerShell 中，可按顺序执行：

```powershell
python --version
python -m venv .venv
.\.venv\Scripts\python.exe --version
.\.venv\Scripts\python.exe -m pip --version
```

第一条确认使用哪个 Python 创建环境；后面用虚拟环境里的解释器检查版本和 pip。也可以直接用这个解释器运行脚本，无需先激活环境。

## 先分清这些东西

| 名称 | 作用 |
| --- | --- |
| Python 标准库 | Python 自带的常用模块，如 `json`、`pathlib` |
| 第三方包 | 项目另行安装的模块 |
| `pip` | 常用的包管理工具 |
| `.venv` | 虚拟环境目录，按项目约定命名 |
| `requirements.txt` | 一种记录第三方依赖的常见方式 |

后续安装依赖时，用目标解释器的 `-m pip`，确认包进入期望的环境。[参考：官方包管理说明](https://docs.python.org/zh-cn/3.13/tutorial/venv.html#managing-packages-with-pip)

## 放到 MindVault 中有什么用

当前 [Markdown 读取小程序](../30-项目实践/01-Markdown读取小程序/README.md) 只用标准库，可以直接运行。以后加入模型 SDK、检索等依赖时，再在项目环境里管理它们。

## 容易误解的地方

- `.venv` 是 Python 环境；`.env` 通常是环境配置文件，两者用途不同。
- 虚拟环境与网页账号、云服务器是不同概念。
- 本库已忽略 `.venv`。换电脑时，根据 Python 版本与依赖说明重新创建环境。
