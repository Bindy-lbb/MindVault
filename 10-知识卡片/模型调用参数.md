# 模型调用参数

[卡片目录](README.md) · [课程入口](../20-课程笔记/第二阶段-模型API课程与实践顺序.md)

## 一句话解释

**调用参数是请求时填写的设置，如模型名、消息、输出上限与返回方式。**像点单的规格，不是模型内部训练权重；改设置不会因此把模型重新训练。

## 为什么需要它

默认值和字段支持会随服务、模型及模式变化。明确本项目实际发送什么，才能解释空返回、截断和参数错误，也能做到一次只改一个设置来比较。

不要把接口完整能力上限、本地教学限制和本次实际用量混成一个数。

## 用 MindVault 走一遍

项目 02 的 hello 请求体示例：

```json
{
  "model":"deepseek-flash",
  "messages":[
    {"role":"system","content":"用一句通俗中文回答。"},
    {"role":"user","content":"请解释 API 的作用，控制在一句话内。"}
  ],
  "max_tokens":300,
  "stream":false,
  "thinking":{"type":"disabled"}
}
```

这是设置输出上限为 300 时的教学请求，不含认证。默认脚本上限为 1200；两者不是固定输出长度。整理任务另加 response_format={type:json_object}，并在规则中要求 JSON。

| 字段 | 做什么 | 易错点 |
| --- | --- | --- |
| model | 选服务模型 | 名称应核对当前文档 |
| messages | 提供任务与材料 | 不会自动读文件 |
| max_tokens | 限制生成长度 | 不等于实际用量 |
| stream=false | 按完整响应处理 | 不用流式分块解析 |
| thinking disabled | 关闭本例思考模式 | 切模式后要核对协议 |
| response_format | 要求返回对象形状 | 不保证业务字段和事实 |

CLI 的 --max-output-tokens 转成 max_tokens，--timeout 是客户端等待设置，不在这份模型请求体里。脚本允许输出上限 1–4096、timeout 1–120 秒，属于教学规则，不是 DeepSeek 全部能力。

当前核查文档仍列 deepseek-flash，但服务可能更新标签对应的后端；运行记录同时保存请求模型和返回模型，便于之后解释差异。

## 每一步的输入输出

| 步骤 | 输入 | 输出 |
| --- | --- | --- |
| 确认服务 | 模型和当前文档 | 支持的字段与模式 |
| 选任务设置 | 输入、格式和长度 | 参数组合 |
| preview | 本地构造 | 可检查请求体 |
| 实际调用 | 认证与参数 | 回答、结束原因、usage |
| 对照 | 相同输入仅改一项 | 效果与用量差异 |

真实请求可能比上限短，也可能因上限而截断，要检查 finish_reason。

## 常见疑问

**temperature=0 就绝对正确吗？**不是，采样设置不是事实验证；具体模式是否支持也要查文档。本项目不设置它。

**stream=false 表示没逐 Token 生成吗？**不是，只是服务以完整响应交付，内部生成机制不同层。

**max_tokens 包含输入吗？**本例用于输出限制，完整上下文和模式预算按服务核对；不要拿它当总费用上限。

**换模型名还需改别的字段吗？**可能需要，接口兼容与模式限制应重新验证。

**输出截断怎么办？**减小任务或适当调整预算并重新验证，不将不完整 JSON 强行保存为可信笔记。

## 小练习与自测

**题目：**max_tokens=300，实际输出 80 Token，属于错误吗？

**参考答案：**不一定，300 是上限，正常提前结束可以更短。

**练习：**只在 preview 改上限，找出变化字段；真实效果要 live，mock 固定回答不能说明参数调优收益。
