# 带引用回答与拒答

[第三阶段阅读顺序](../20-课程笔记/第三阶段-RAG课程与实践顺序.md) · [项目 03](../30-项目实践/03-RAG知识库问答/README.md)

## 一句话解释

**带引用回答要能把结论追溯到具体原文；依据不足时，要说明当前无法可靠回答。**这里的“拒答”主要指资料不足时停止猜测，不等于所有情况下都完全不提供帮助。

## 为什么需要它

模型可以把句子写得很流畅，但读者还需要知道：这句话从哪来？原文真的这样说吗？有没有遗漏条件？

单独附一个文件名只能提供线索。一个可靠的核对过程还需要具体片段和原句，并判断原句能否支持答案。引用格式正确、原句存在，都不能自动证明模型解释正确。

## 用 MindVault 走一遍

问题：“API 密钥应该放在哪里，能写进 Git 吗？”本次假设选中了 [API 配置示例](../30-项目实践/03-RAG知识库问答/examples/notes/01-API配置.md)中同时包含以下两句的片段，并临时编号为 S1：

> API 密钥用于认证调用方，建议放在本地环境变量中。
> 不要把真实 API 密钥写进 Markdown、代码或 Git 提交。

一份教学用回答结构可以是：

```json
{
  "answer": "资料建议把 API 密钥放在本地环境变量中，不要把真实密钥写入 Git 提交。",
  "citations": [
    {"source_id": "S1", "quote": "API 密钥用于认证调用方，建议放在本地环境变量中。"},
    {"source_id": "S1", "quote": "不要把真实 API 密钥写进 Markdown、代码或 Git 提交。"}
  ],
  "insufficient_evidence": false
}
```

这是根据本库原文手写的示例，没有冒充真实模型响应。`answer` 是答案，`citations` 是引用列表，`source_id` 指向本次提供的材料，`quote` 是逐字原句，最后的布尔值说明是否缺少充分依据。

## 每一步的输入输出

| 步骤 | 输入 | 输出或检查 |
| --- | --- | --- |
| 给来源编号 | 本次选中的片段 | S1、S2 等临时编号 |
| 构造请求 | 问题、片段、回答规则 | 模型请求内容 |
| 生成 | 模型实际收到的请求 | 待核对答案和引用 |
| 检查来源 | 返回的 source_id | 编号是否存在于本次材料 |
| 检查原句 | quote 和对应片段 | 原句是否逐字出现 |
| 检查含义 | 答案、原句及上下文 | 是否支持结论、是否遗漏限制 |

例如，模型回答“真实密钥可以提交到 Git”，却引用“不要把真实 API 密钥写进……Git 提交”。编号和引文都是真的，含义却完全相反。本脚本能自动检查编号与原句，语义是否支持结论仍需人工判断。

## 什么时候应该说明依据不足

如果你问“我的密钥是哪一天创建的”，上述材料没有个人账户记录。可回答“当前资料没有提供创建日期”，并说明需要查看什么信息，而不是猜一个日期。

有些问题只得到部分证据。例如材料解释保存位置，却没有轮换周期要求，就应明确哪些部分有依据、哪些部分未知。当前教学脚本采用整体的 `insufficient_evidence` 标记：标为 true 时引用列表须为空；更细的逐结论部分回答，需要扩展结构和校验。

零命中时，本库直接返回依据不足提示，不发真实模型请求。但零命中也可能是检索漏掉了答案，因此表述应限定在“当前检索依据”。

## 常见疑问

**检索到了三个片段，就有答案了吗？** 三段文字可能只是在主题上相近，仍没有回答问题所需的事实。

**原文也有错误怎么办？** 引用证明出处，不证明事实本身。需要核对版本、来源可信程度和相互冲突的材料。

**给模型写“不要胡说”就够了吗？** 还需要限定可读资料、限制工具权限、检查输出。资料中出现“忽略之前规则”等文字时，应作为被阅读的内容，不能当成新的控制指令。

## 小练习与自测

比较两个答案：“资料建议环境变量保存密钥”和“资料证明环境变量在任何情况下都绝对安全”。同一条引文能支持哪一个？

参考答案：它支持第一句的存储建议，没有证明“任何情况下绝对安全”。第二句扩大了原文结论。
