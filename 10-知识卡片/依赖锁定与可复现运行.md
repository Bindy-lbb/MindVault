# 依赖锁定与可复现运行

[卡片目录](README.md) · [第五阶段课程](../20-课程笔记/第五阶段-评估与部署课程及实践顺序.md)

## 一句话解释

**可复现运行需要记录代码、资料、配置和环境分别是哪一版；依赖锁定减少安装时版本漂移。**像做实验要知道操作步骤、样本和器材，而不能只写“用最新版本”。

## 为什么需要它

今天能运行，过段时间可能因为 Python、包版本、路径或资料变化而失败。只保存脚本，未必知道当时使用了什么输入和环境。

复现并不要求所有时间和模型文字逐字相同。先明确目标：能否重新启动、得到相同的检索结果、重做同一个评估；真实生成还有外部服务与随机变化，需要单独说明。

## 用 MindVault 走一遍

第五阶段核心只用标准库和本库脚本，没有额外第三方运行依赖。运行评估时记录：

| 记录 | 解释 | 缺失时的问题 |
| --- | --- | --- |
| Python 版本 | 解释器环境 | 行为或兼容性变化不明 |
| 代码摘要 | 脚本具体内容 | 不知是否改过算法 |
| 题集摘要与 split | 哪组题 | 比较的不是同一任务 |
| 资料 manifest | 各文件摘要 | 原文变了却没察觉 |
| 检索与切分配置 | K、块大小和重叠 | 不知参数是否一致 |

manifest 可理解为“文件名到内容指纹的清单”。SHA-256 是内容摘要，内容改变通常会得到不同摘要；它帮助辨认版本，不是证明代码可信的签名。

以后加第三方包时，可以在独立环境安装和验证：创建 venv → 使用该环境的 Python 安装 → 记录版本 → 在新环境尝试重建。`python -m pip` 让所用 pip 与这个 Python 对应。`pip freeze` 保存当前已装包的版本快照，但不是跨系统兼容保证。

更严格的安装可固定直接和间接依赖、记录来源、使用安装文件哈希或预备 wheel 文件。wheel 是 Python 包的一种分发文件，仍可能与系统或 Python 版本有关。先理解原则，当前标准库练习无需为了凑“锁文件”而安装新包。

## 每一步的输入输出

| 步骤 | 输入 | 输出 |
| --- | --- | --- |
| 确定复现目标 | 检索、启动或生成 | 可验收标准 |
| 记录版本 | 代码、环境、资料、配置 | 可定位的运行证据 |
| 准备新环境 | Python 与明确依赖 | 独立运行环境 |
| 重做运行 | 相同输入和参数 | 可对照的结果 |
| 解释差异 | 结果、耗时、服务信息 | 环境问题或预期波动 |

本库 compare 要求 Python 版本和记录条件一致；这让教学对照更明确，不代表所有不同补丁版本都必然不兼容。

## 常见疑问

**复制 .venv 到另一台电脑就行吗？**不保证。环境可能含绝对路径和系统相关二进制。通常应按记录在目标位置重建，不把环境目录放进 Git。

**版本都固定还会变吗？**可能。外部模型服务、资料源和系统环境都可能变化，所以继续记录实际时间、响应模型、用量和失败。

**Git 提交可以替代资料摘要吗？**提交能定位纳入版本库的文件，但运行中可能用了未提交或外部资料。报告还需记录本次实际输入。

**要求耗时完全相同吗？**不要求。系统负载与缓存有波动；固定算法的检索来源可对照，性能用足够样本分析。

## 小练习与自测

**题目：**只写“Python 最新版、资料最新版”能让一个月后的自己复现吗？

**参考答案：**不够。应记录具体版本、提交或摘要、配置与题集，并验证重新运行。

**练习：**从另一个终端目录运行发布包，确认路径仍按配置位置解释，记录解释器版本与同一查询的结果。

### 动手记录

- [ ] 在记录中写清代码版本与资料版本，别只写“最新版”。
