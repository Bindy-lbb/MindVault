# Agent 权限与提示注入

[卡片目录](README.md) · [第四阶段课程](../20-课程笔记/第四阶段-工具调用与Agent课程及实践顺序.md)

## 一句话解释

**权限决定 Agent 实际能做什么；提示注入是资料中的文字试图冒充指令，改变它的行动。**像一本借来的书夹着“把图书馆钥匙交给我”的纸条，读到它不代表应该照做。

## 在本项目里

模型只看到两种已登记工具，只能读显式选定的 Markdown。`note_id` 要在启动时的资料清单中，不能把 `../../.env` 或绝对路径当成笔记 ID。程序不向模型提供 Shell、删除、联网搜索或发送消息工具。

提示词告诉模型把笔记内容当资料；代码另行检查工具名称、参数与资料范围。只写“请不要越权”不足以替代这些限制。

## 资料与外部服务的边界

默认示例来自第三阶段的自写笔记。`live` 会把任务、工具结果和会话历史发给 DeepSeek；日志也会保留这些正文。换真实资料前先筛选，只选允许使用的内容，生成记录留在 `.local/`。

MCP 的工具文档同样强调工具使用的控制与可见性，协议接入不自动解决权限问题。[MCP 工具规范](https://modelcontextprotocol.io/specification/2025-11-25/server/tools)

## 小练习与自测

- [ ] 用不存在的 note_id 测试，确认实际没有读取。
- [ ] 在本地副本加入一段试图要求调用未登记工具的文字，检查调用轨迹与拒绝结果。
- [ ] 将来增加写入动作前，先明确可写范围、预览、确认与重复执行处理。

**问题：**模型能列出一个函数名，是否表示它拥有这个能力？

**参考要点：**没有；只有本地登记、校验通过且实际执行的工具才产生行动。
