# 版本发布与回滚

[卡片目录](README.md) · [第五阶段课程](../20-课程笔记/第五阶段-评估与部署课程及实践顺序.md)

## 一句话解释

**发布把一组明确版本的文件作为可运行成果保存；回滚是在新版本有问题时重新运行已验证的旧版本。**像保留一份好用的复习计划，修改不合适时能回到它。

## 本项目的本地发布包

保存服务脚本、检索脚本、允许的样例资料、配置和文件 SHA-256 清单。版本号是人的标记，文件摘要用于核对实际内容；清单不是数字签名，不证明作者身份或没有恶意代码。

不复制密钥、Git 历史、日志、虚拟环境或已有索引。索引需在发布包最终位置重新建立，以免引用旧机器的绝对路径。

## 怎样做一次回滚演练

保留 v1 目录 → 把 v2 建到另一个新目录 → 检查评估与启动 → v2 出问题时停止它 → 重新启动 v1 → 检查 ready 与同一查询。当前没有数据库迁移或外部写入，回滚只涉及本地程序与选定资料。

FastAPI 部署概念强调启动、重启与运行管理；本库在此基础上提供版本目录与文件清单练习。[官方概念参考](https://fastapi.tiangolo.com/deployment/concepts/)

## Git 提交与运行发布的区别

提交说明代码保存到了仓库；服务是否启动、配置是否正确、资料是否可用还需另查。当前打包是本地操作，不自动创建 GitHub Release 或公开网站。

## 小练习与自测

- [ ] 打包后核对文件摘要，改动一个实验文件观察校验失败。
- [ ] 重启旧发布目录，用同一问题验证恢复结果。

**问题：**有版本号，但没有保存对应文件，还能可靠回滚吗？

**参考要点：**很难；要保留代码、配置、资料版本和恢复步骤，且验证能运行。
