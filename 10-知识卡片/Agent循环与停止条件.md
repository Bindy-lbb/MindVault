# Agent 循环与停止条件

[卡片目录](README.md) · [第四阶段课程](../20-课程笔记/第四阶段-工具调用与Agent课程及实践顺序.md)

## 一句话解释

**Agent 循环就是“选择行动 → 执行 → 收到反馈 → 再选择”；停止条件给它一个明确终点。**好比查资料要知道什么时候可以写答案，也要知道查不到时何时收手。

## 为什么需要它

模型可能重复搜索，材料也可能一直不足。如果只告诉它“完成后停止”，并不能保证它一定及时结束。程序要限制请求次数、工具尝试次数和消息长度，并记录结束原因。

停止不等于成功。一次任务可能因为完成、依据不足、预算到顶、API 错误或最终内容不合格而停止。把它们统一写成“已完成”会掩盖真正的问题。

## 用 MindVault 走一遍

成功演示共有三轮：第一轮请求搜索，第二轮请求读取，第三轮返回题目。因此是 **3 次预写响应、2 次工具尝试**；scripted 没有实际模型请求费用。

参数修正演示多一次失败搜索：错误搜索 → 正确搜索 → 读取 → 最终题目，得到 **4 次响应、3 次工具尝试**。错误参数虽然没完成搜索，也占一次尝试预算。

| 限制 | 当前默认或约定 | 含义 |
| --- | --- | --- |
| max_rounds | 默认 6 | 每次请求尝试计数，最终回答那次也算 |
| max_tool_calls | 默认 6 | 每次实际进入工具处理的尝试计数 |
| 会话字符预算 | 24000 | 序列化 messages 与 TOOLS 长度合计 |
| 单次 API 等待 | 60 秒 | 不是整项任务的总时长 |

假设一轮提出两个调用，两个都被处理，就是 1 次请求、2 次工具尝试。如果只剩一个工具名额，第一个可以处理，第二个会触发工具上限并结束，不再继续请求模型。

重复调用演示用 `--max-rounds 2` 时，两次搜索后退出为 round_limit。用 `--max-rounds 6 --max-tool-calls 1` 时，第二轮提出调用后触发 tool_limit，只有第一次工具被处理。

## 每一步的输入输出

| 步骤 | 输入 | 输出 |
| --- | --- | --- |
| 检查上下文 | 当前消息与工具声明 | 可请求，或 context_limit |
| 请求下一步 | 会话 | 工具调用、最终内容或错误 |
| 处理调用 | 剩余工具预算 | 工具结果，或 tool_limit |
| 验证最终内容 | JSON 与已读依据 | completed、insufficient_evidence 或 invalid_final |
| 用尽轮数 | 尚未返回最终内容 | round_limit |

本库没有单独的“重复内容检测器”；重复行为主要由次数预算兜底。

## 常见疑问

**completed 就代表题目一定正确吗？**不是。它表示通过当前字段、类型和逐字引文检查，答案是否被引文支持仍需人工核对。

**max_rounds=6 能精确限制费用吗？**不能。不同轮次输入长度不同，工具结果也会累积；需要结合实际 usage 和计费规则。字符数也不是 Token 数。

**最后一轮刚好用完工具名额，为什么可能显示 round_limit？**停止标签取决于实际触发的分支。若循环已自然耗尽轮数，没有再尝试处理下一条调用，就可能记为 round_limit；别只根据计数猜标签。

## 小练习与自测

**题目：**两轮中第一轮提出搜索和读取，第二轮给最终内容，共几轮、几次工具？

**参考答案：**2 轮、2 次工具尝试，前提是调用都被程序接受并处理。最终内容这一轮也计数。

**练习：**分别运行两个小预算的 loop 情节，对照上面的计数，检查 result.md 的停止原因。不要把预算结束标为任务成功。
