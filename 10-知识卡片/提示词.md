# 提示词

[知识卡片目录](README.md) · [学习地图](../学习地图.md)

## 一句话解释

**提示词是你提供给模型的任务输入，可以包含要做什么、参考材料、要求和输出示例。**清楚地表达目标，有助于模型给出符合需求的结果。[依据：Anthropic 提示词指南](https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/claude-prompting-best-practices#be-clear-and-direct)

## 用生活里的事理解

像给同事一张任务单。“整理一下”留下很多猜测空间；说清楚材料、重点和交付格式，对方更容易执行。

同样，提示词中的“词”不表示只能写几个关键词。需要时可以使用完整句子、例子和分段说明。

## 一个具体例子

**自拟教学提示词：**把下面这段内容与真实文章正文一起提供给模型。

```text
请根据我提供的文章正文，整理一份面向初学者的 Markdown 笔记。

要求：
1. 用三句话概括文章。
2. 列出三个关键概念，并用通俗语言解释。
3. 重要观点标出对应段落或原文依据。
4. 原文没说明的信息写“原文未提供”。
5. 额外的学习建议单独列出。

文章标题、链接和正文：在这里粘贴实际材料。
```

这是练习模板；使用时填入材料，再检查实际生成的结果。

## 我可以怎样写清楚任务

| 部分 | 要回答的问题 |
| --- | --- |
| 目标 | 希望模型完成哪件事？ |
| 材料 | 它应参考哪段文章、哪些笔记？ |
| 约束 | 面向谁、关注什么、哪些信息需核对？ |
| 格式 | 要 Markdown、列表还是 JSON？ |
| 示例 | 有没有一小段期望的输出样式？ |

这些是本卡片整理的检查项，可按任务取用。官方指南也建议用清晰说明和相关示例表达预期。[参考：Anthropic 提示词指南](https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/claude-prompting-best-practices)

## 容易误解的地方

- 只给文章链接，不代表应用一定能读取正文；需要确认实际提供了什么 [上下文](上下文.md)。
- 写得很长不一定有帮助，清楚、相关的要求更有用。
- 普通提示词修改不会改变模型权重，也不能保证完全消除 [幻觉](幻觉.md)。[提示词与参数依据：Google](https://developers.google.com/machine-learning/crash-course/llm/tuning#prompt-engineering)

## 放到 MindVault 中有什么用

把有效的文章整理要求保留在项目记录中，逐步比较不同版本。阶段 2 再把这份任务说明放进 [API](API.md) 请求。

## 我的理解与验证

- [ ] 用同一篇文章比较“帮我总结”和上面的具体要求，记录可观察的差别。
- [ ] 只调整一个要求，看看格式或重点是否变化。
- [ ] 回到原文核对三个关键说法，记录依据。

## 自测与参考答案

**问题：**写一份新的提示词，是否等于重新训练模型？

**参考要点：**普通提示是在本次输入中说明任务，利用现有模型能力；训练涉及调整模型内部参数。详细区分见 [训练与推理](训练与推理.md)。
