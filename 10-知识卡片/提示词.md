# 提示词

[卡片目录](README.md) · [课程入口](../20-课程笔记/第一阶段-线上课程与阅读顺序.md)

## 一句话解释

**提示词是交给模型的任务说明与输入，可包含目标、材料、约束、输出格式和例子。**像一张交付说明单：越清楚地写出要做什么，越容易核对结果是否符合要求。

## 为什么需要它

“整理一下”留给模型大量猜测空间：写多长、关注什么、能否补充背景、怎么保存？先明确这些，比只增加“你是专家”更便于检验效果。

提示词可以帮助表达任务，但不直接修改权重，也不能替代事实核对。

## 用 MindVault 走一遍

对《从记录到复习》，可用下面的自写任务说明；真正使用时要提供正文：

```text
根据下面文章，为初学者整理笔记。
1. 摘要写 1–3 句。
2. 列 1–5 个原文观点，每项附逐字短依据。
3. 原文没说的作者、时间和结论不要补造。
4. 待研究问题与额外建议单独列出。
5. 输出为约定 JSON，不加解释性文字。
文章正文：在这里放入实际正文。
```

| 部分 | 回答的问题 | 验收方式 |
| --- | --- | --- |
| 目标 | 为谁整理什么 | 是否便于初学者理解 |
| 材料 | 参考哪段正文 | 观点能否回原文 |
| 约束 | 哪些信息不可补造 | 缺失信息是否说明 |
| 格式 | 返回哪些字段 | 程序检查字段和类型 |
| 示例 | 期望怎样组织 | 对照一个合格样例 |

当前程序将规则放进 system，正文放进 user，并明确正文中的改变任务要求作为资料处理。规则声明有帮助，仍要由校验代码落实能自动检查的限制。

比较提示词时用同一篇文章、相同模型设置，一次只改一项要求。mock 的结果是固定文件，不会因提示改了就自动重新理解文章；真正效果变化需要 live 后观察。

## 每一步的输入输出

| 步骤 | 输入 | 输出 |
| --- | --- | --- |
| 定目标 | 具体学习需要 | 可判断的任务 |
| 选材料 | 相关正文 | 实际上下文 |
| 定约束和格式 | 事实边界、字段、数量 | 清楚说明与示例 |
| 查看请求 | 完整 messages | 确认材料和要求已传入 |
| 评价修改 | 原文与实际输出 | 改善、失败和下一步 |

长提示词未必好，重复或冲突要求可能降低可执行性。优先保证清楚且相关。

## 常见疑问

**只贴文章链接够吗？**本脚本不抓链接，必须提供正文。

**“请保证正确”能省略验证吗？**不能，应设计可以回查的依据和验收规则。

**加很多角色称号一定有效吗？**关键是具体任务、材料和可检查标准，用同题结果判断。

**普通提示是不是微调？**不是，提示只改变本次输入；微调涉及参数更新。

**示例答案可以替代原文吗？**格式示例用于表达形状，不应让模型把示例事实误当目标文章内容。

## 小练习与自测

**题目：**只改摘要句数，离线 mock 输出没变，是提示无效吗？

**参考答案：**mock 不调用模型，固定内容不反映提示效果；它只演练处理流程。

**练习：**为熟悉文章写五项任务要求，列出可验证条件，再记录一次只改一个要求的对照。

### 动手记录

- [ ] 用同一篇文章比较“帮我总结”和上面的具体要求，记录可观察的差别。
- [ ] 只调整一个要求，看看格式或重点是否变化。
- [ ] 回到原文核对三个关键说法，记录依据。
- [ ] 哪种文章整理格式最适合我复习？通过后续实践比较。
