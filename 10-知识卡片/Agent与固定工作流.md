# Agent 与固定工作流

[卡片目录](README.md) · [第四阶段课程](../20-课程笔记/第四阶段-工具调用与Agent课程及实践顺序.md)

## 一句话解释

**固定工作流由程序预先安排路径；Agent 让模型根据任务和行动反馈选择下一步。**可以把前者理解为照着复习清单做事，后者理解为发现不会的题后，临时决定再翻哪份资料。

这里的 Agent 指“模型参与决策的执行系统”，包括模型、工具、状态和控制代码。它不只是一个提示词，也不一定有聊天界面。不同教程的术语范围可能不同，判断时先问：这一步是谁决定的？

## 为什么需要它

第三阶段已经能“找材料再回答”。第四阶段增加的是行动选择：该搜索还是读取？材料不足要不要换词？什么时候可以出题？

如果每次都做相同步骤，让代码固定执行更容易检查。如果输入不同，需要根据返回结果改变路线，模型决策才可能有价值。增加 Agent 循环也会增加请求次数、延迟和出错位置，所以先把两个工具单独跑通。

## 用 MindVault 走一遍

贯穿任务是：“根据 API 密钥笔记，生成一条复习题，并给出答案和逐字依据。”默认资料是第三阶段的五篇示例笔记。

**固定流程**：代码搜索 `API 密钥环境变量`，取第一条命中，读取对应行，展示原文。当前 `workflow` 到此结束，没有生成复习题。

**动态 Agent 的可能过程**：模型请求搜索，看到 `01-API配置.md`，再请求读取；如果没找到相关内容，可以换关键词，也可以说明依据不足。真实行动仍要经过代码校验。

**本库 scripted 演示**：搜索、读取、出题三步已经写在响应文件中。工具真的执行，但“选哪一步”和最后的题目都预先写好。它适合学习消息如何流动，不能证明真实模型会做同样选择。

| 模式 | 谁决定步骤 | 有没有模型请求 | 得到什么 |
| --- | --- | --- | --- |
| tool | 你指定工具与参数 | 无 | 一次工具返回 |
| workflow | 代码固定路径 | 无 | 搜索和读取的原文 |
| scripted | 教学响应文件 | 无 | 预设情节的执行记录 |
| preview | 只构造初始请求 | 无 | 将发送的请求结构 |
| live | 模型提出下一步 | 有 | 实际调用后的结果或失败 |

这五个模式是本项目的命名，不是行业通用协议。

## 每一步的输入输出

| 步骤 | 输入 | 输出与责任 |
| --- | --- | --- |
| 确定目标 | 出一道密钥复习题 | 用户规定任务 |
| 搜索 | 关键词 | 工具返回候选资料 |
| 选择读取 | 候选 ID 和行号 | workflow 用代码选；live 由模型提议 |
| 读取 | 合法 ID 和范围 | 程序返回原文 |
| 完成或继续 | 原文、任务、剩余预算 | Agent 返回题目或继续；固定流程按设计结束 |

## 常见疑问

**用了 LangGraph 就是 Agent 吗？**不是。当前选修图是 `START → search → read → END`，路径固定，且没有模型请求。框架帮助组织状态和步骤，不能替代对决策方式的判断。

**有循环就算 Agent 吗？**不是。每隔一秒重试同一个函数也是循环，决策仍完全固定。

**RAG 和 Agent 是二选一吗？**不是。RAG 关注检索材料来辅助生成，Agent 关注根据反馈安排动作；Agent 可以把检索当工具，也可以完全不使用知识库。

## 小练习与自测

**题目 1：**每天把新笔记按日期列成目录，需要动态 Agent 吗？

**参考答案：**通常固定脚本就能完成。只有任务需要理解内容并动态选择处理方法时，再评估模型决策是否值得加入。

**题目 2：**scripted 成功生成一道题，能记为“真实模型测试通过”吗？

**参考答案：**不能。应记为“预写响应驱动，工具真实执行，未调用模型”。
