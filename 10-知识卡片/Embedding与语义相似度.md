# Embedding 与语义相似度

[第三阶段阅读顺序](../20-课程笔记/第三阶段-RAG课程与实践顺序.md) · [项目 03](../30-项目实践/03-RAG知识库问答/README.md)

## 一句话解释

**Embedding 把文本转成一串数值，让程序能够计算两段文字的表示有多接近。**这串数值叫向量。语义检索用它寻找措辞不同、含义可能相关的材料。

“含义坐标”是帮助入门的类比。真实模型的每一维通常不能直接命名为“安全程度”“密钥程度”，也不能把向量当作一份人能直接读懂的摘要。

## 为什么需要它

笔记写“API 密钥建议放在环境变量中”，你可能问“程序的访问凭证应该保存在哪儿？”两句话字面重合少，简单关键词检索容易漏掉。

Embedding 模型通过训练学到文本表示，使一些语义相关的表达更容易被匹配。它可能帮助找到上述笔记，但不保证一定成功；“钥匙应该存哪儿？”太含糊，还可能指家门钥匙。

Embedding 模型负责产生向量，生成模型负责组织回答。RAG 中可以分别选用这两类能力，语义检索本身不会写出完整答案。

## 用 MindVault 走一遍

准备资料时，把每个笔记片段输入 Embedding 模型，得到向量，和片段 ID、原文及来源一起保存。提问时，再把“API 密钥应该放在哪里，能写进 Git 吗？”编码成问题向量，与片段向量比较，返回较接近的片段。

下面是手工构造的二维向量，仅用于学习计算，**不是模型对真实句子的输出**：

| 对象 | 向量 | 与问题向量的点积 |
| --- | --- | --- |
| 问题 Q | `[1, 0]` | 与自己比较是 1 |
| 片段 A | `[0.8, 0.6]` | `1×0.8 + 0×0.6 = 0.8` |
| 片段 B | `[0, 1]` | `1×0 + 0×1 = 0` |

三组向量的长度都是 1，因此这个例子中点积也等于余弦相似度。A 的分数更高，于是会排在 B 前面。但 0.8 并不表示“答案有 80% 概率正确”，它只表示这个比较方法下的相似程度。

一般情况下，余弦相似度是“点积 ÷ 两个向量长度的乘积”。把非零向量缩放到长度 1 叫归一化；这样计算点积就能得到余弦相似度。本项目语义路径使用归一化向量。

## 每一步的输入输出

| 步骤 | 输入 | 输出 |
| --- | --- | --- |
| 文档编码 | 一个片段 | 固定维度的数值向量 |
| 保存 | 向量、片段 ID 和来源 | 可对应回原文的记录 |
| 问题编码 | 用户的问题 | 与文档表示兼容的问题向量 |
| 比较 | 问题向量与各片段向量 | 相似度分数 |
| 取回材料 | 排名前列的片段 ID | 原文及来源，而不只是数字 |

“维度”就是数值个数，例如 384 维意味着一段文字得到 384 个数。它不表示只能处理 384 个字，输入长度是另一项限制。

## 常见疑问

**同样是 384 维就能比较吗？** 不一定。不同模型学到的坐标体系可能不同。建库和提问应使用兼容模型与编码规则；某些模型对问题和文档分别要求不同前缀，也需要遵循。换模型后通常应重算文档向量。

**长文章整篇编码不是更方便吗？** 模型有输入长度限制，超长文本可能截断；多个主题混在一起，也可能降低定位某个细节的效果。因此先切成合适片段，再检查实际长度。

**高相似度一定能回答问题吗？** “密钥”“Git”主题相关，不代表片段包含“是否允许提交”的证据。否定、日期、产品型号等细节仍需核对。

**转换成向量后就保密了吗？** 向量不等于加密或匿名化承诺；索引往往还保存原文与路径，分享前仍需检查内容。

## 小练习与自测

对手写向量 Q=`[1,0]`、C=`[-1,0]` 算一次余弦相似度；再回答：为何不能把这个分数叫“正确率”？

参考答案：它们都是单位向量，点积为 -1，表示本例的方向相反。该计算没有检查事实、引用或答案正确性，因此不能解释成正确率。
