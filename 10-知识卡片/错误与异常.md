# 错误与异常

[卡片目录](README.md) · [课程入口](../20-课程笔记/第一阶段-线上课程与阅读顺序.md)

## 一句话解释

**错误信息是定位问题的线索；异常是执行时发现无法按正常路径继续的信号。**像拿资料时发现地址不存在，应先检查地址，而不是假装资料已取回。

## 为什么需要它

学习程序不会每次都成功。文件缺失、类型错误、JSON 格式错误和网络失败需要不同处理。读懂类型、位置和输入，才能有依据地改正。

捕获异常是把问题交给合适层处理，不是把所有失败都改成“完成”。

## 用 MindVault 走一遍

先用一个完整、自写、无需文件的例子观察转换失败：

```python
text = "不是数字"
try:
    count = int(text)
    print(count)
except ValueError:
    print("请提供能转换成整数的文字")
```

会显示提示而非成功 count。try 是尝试执行的区域，except ValueError 只处理对应类型错误。真实问题仍未变成有效数字，需要用户修正输入。

| 情况 | 常见信号 | 先查什么 |
| --- | --- | --- |
| 缺引号或冒号 | SyntaxError | 代码语法与前后行 |
| 文件不存在 | FileNotFoundError | 路径、工作目录、文件名 |
| 输出已存在 | FileExistsError | 是否该换新输出名 |
| 数字与文字混用 | TypeError 或 ValueError | 类型与转换 |
| 字典缺字段 | KeyError | 返回结构和键名 |
| 非法 JSON | JSONDecodeError | 引号、逗号、纯 JSON 内容 |

没有被处理时，Python 通常显示 traceback 调用栈。从末尾看异常类型与消息，再看自己的文件和行号，往回追输入来源。报错指向的是检测位置，根因也可能在更早输入或代码处。

## 每一步的输入输出

| 步骤 | 输入 | 输出 |
| --- | --- | --- |
| 重现 | 原命令、输入与环境 | 可重复的失败 |
| 读错误 | 类型、消息、调用位置 | 初步层次判断 |
| 查原因 | 路径、字段、参数等 | 最小修复假设 |
| 修改一项 | 有依据的修正 | 新运行结果 |
| 记录 | 成功和失败证据 | 下次可参考的处理方法 |

日志可以记录模式、错误和规模，不需要把真实密钥或全部私人正文打印出来。

## 常见疑问

**报错就说明模型坏了吗？**很多错误发生在文件、输入和网络阶段，模型甚至没被调用。

**except 后什么也不做可以吗？**会隐藏失败，后面可能继续处理无效数据。至少明确停止或返回可识别状态。

**要把所有异常都 catch 吗？**按可以合理处理的情况捕获。未知问题保留必要线索，别统一伪装成空结果。

**脚本返回 0 就是内容全对吗？**通常表示程序约定的成功结束，不自动证明事实正确。

**重试能解决语法错吗？**输入或代码不变，反复执行一般不会改变根因。
