# 部署方式与访问控制

[卡片目录](README.md) · [第五阶段课程](../20-课程笔记/第五阶段-评估与部署课程及实践顺序.md)

## 一句话解释

**部署决定程序在哪里运行，访问控制决定谁能使用它、能看到哪些资料。**像把书放在个人书桌、办公室或公共图书馆，需要不同的开放方式。

## 三种常见选择

| 方式 | 适用情况 | 需要确认 |
| --- | --- | --- |
| 本机命令行/回环服务 | 自己学习，快速检查 | Python、资料位置、启动停止 |
| 托管应用平台 | 希望浏览器访问与分享 | 平台支持、可见性、密钥、数据与费用 |
| 自管服务器 | 有特定网络或运行要求 | HTTPS、认证、进程管理、重启、日志与运维 |

FastAPI 部署文档讨论 HTTPS、启动、重启、复制与资源等问题；本项目只完成本机教学服务，没代为创建云资源。[部署概念](https://fastapi.tiangolo.com/deployment/concepts/)

## GitHub 私有不等于网页访问已配置

仓库用于保存代码与笔记，应用平台另有自己的权限设置。Streamlit 当前文档说明应用可继承仓库可见性并可在设置中更改，还有限制；部署时应重新核对，不只看仓库锁图标。[分享文档](https://docs.streamlit.io/deploy/streamlit-community-cloud/share-your-app)

当前没有公开 MindVault，也没有把本地服务改成外网监听。云部署作为后续选修，先用可公开的样例与单独应用仓库验证。

## 小练习与自测

- [ ] 写清自己只需本机使用，还是确实需要多人访问。
- [ ] 设计一个已登录用户和未登录用户的访问验证方法。

**问题：**把监听地址换成 0.0.0.0 就完成上线了吗？

**参考要点：**没有；还要处理访问权限、网络、HTTPS、可靠运行和数据边界。
