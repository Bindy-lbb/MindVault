# 部署方式与访问控制

[卡片目录](README.md) · [第五阶段课程](../20-课程笔记/第五阶段-评估与部署课程及实践顺序.md)

## 一句话解释

**部署决定程序在哪里运行，访问控制决定谁能使用、能看到什么。**像资料放个人书桌、办公室或公共图书馆，需要不同的开放范围。

“能打开网页”与“只让该看的人看到”是两个验收问题，应分别验证。

## 为什么需要它

本机学习不一定需要服务器；多人使用又不能只靠把程序传到云端。模型、资料、密钥和日志都可能跨越原来的电脑范围。

先问谁需要使用、需要哪些资料和多久可用，再选运行方式。这样可以避免为了一个自己用的工具，过早承担维护服务的复杂度。

## 用 MindVault 走一遍

MindVault 当前保存在私有 GitHub，Obsidian 阅读本地笔记；项目 05 可以启动本机检索 API。这三件事分别负责笔记保存、阅读和检索服务。

| 方式 | 适合什么 | 需要负责什么 |
| --- | --- | --- |
| 本机命令行或回环服务 | 自己练习与验证 | Python、资料位置、启动停止 |
| 托管应用平台 | 需要浏览器界面和分享 | 入口、依赖、可见性、密钥及平台限制 |
| 自管服务器 | 特定网络、资源或运行要求 | 系统、HTTPS、认证、重启、日志与维护 |

127.0.0.1 是每台设备自己的回环地址。把本机地址发给朋友，朋友打开的是他自己的电脑，不会连到你的服务。0.0.0.0 是常见的全接口监听配置，不是给人访问的具体网址，也不自动补上权限或 HTTPS；本项目没有这个监听开关。

未来要分享，可以先用可公开的示例和单独应用做验证，不需要让整座 MindVault 跟着公开。仓库私有与应用访问设置是不同层：平台可能继承仓库初始权限，也可能支持单独修改，部署时应核对实际设置和账户条件。

访问控制还分两层：认证回答“你是谁”，授权回答“你可以读什么、做什么”。登录成功不代表应读所有人的笔记。未来多用户检索要在返回资料之前过滤权限，不能只在网页隐藏链接。

## 每一步的输入输出

| 步骤 | 输入 | 输出 |
| --- | --- | --- |
| 明确需求 | 单人或多人、资料范围 | 本机或远程方案 |
| 选运行方式 | 界面/API、资源、维护能力 | 适配平台的应用入口 |
| 设计访问 | 身份、角色、资料边界 | 认证与授权规则 |
| 验证功能 | 启动、就绪、查询 | 可用的运行证据 |
| 验证权限 | 登录、未登录和不同权限用户 | 允许与拒绝的实际结果 |

HTTPS 保护传输链路，不替代用户权限；进程管理负责启动与异常重启，不替代答案质量评估。

## 常见疑问

**把私有仓库连上平台就一定只有自己能看吗？**不能只看仓库锁图标。核对平台的应用可见性、邀请和分享设置，用未登录窗口实际检查。

**当前包能直接上传成 Streamlit 网页吗？**它是标准库 JSON API，没有 Streamlit 应用入口；若选该平台，需要另做页面与依赖配置。

**装 FastAPI 就算生产部署了吗？**还需服务进程、HTTPS、启动与重启、权限、资源和日志等配置。框架只是应用的一部分。

**本机回环就等于有登录保护吗？**不是。它缩小网络访问范围，却没有用户身份隔离；本机其他可访问该端口的程序也可能发请求。

**需要现在买云服务器吗？**当前个人学习目标可先在本机完成。只有确实需要远程访问，再按资源与维护需求核实平台和费用。

## 小练习与自测

**题目：**同一用户能登录，但本不应看的笔记也被搜出来，缺哪一层？

**参考答案：**认证可能完成了，资料授权没有落实。应在检索和返回阶段按权限限制来源。

**设计练习：**写出自己是否需要远程使用，再设计未登录、允许用户、无资料权限用户各一次验证。当前本地服务未实现这些多用户能力，方案先记为待实现。
