# 工具调用与 Function Calling

[卡片目录](README.md) · [第四阶段课程](../20-课程笔记/第四阶段-工具调用与Agent课程及实践顺序.md)

## 一句话解释

**Function Calling 是模型用约定格式提出工具请求，应用程序检查后执行函数，再把结果交回模型。**像填写借书单：写下书名不等于书已经拿到手，必须由借阅系统实际办理。

“工具”在本项目中就是一段有名字、参数和返回值的 Python 功能。模型负责提出行动，执行代码负责落实行动。

## 为什么需要它

模型不会因为你在聊天里提到 MindVault 就自动打开电脑里的笔记。程序必须提供可调用的搜索、读取能力，并把执行结果放进后续请求。

这样可以把“猜测笔记里可能有什么”变成“根据实际读到的文字回答”。但有工具仍可能选错关键词、读错段落或误解原文，所以还要看轨迹和答案。

## 用 MindVault 走一遍

任务仍是根据 API 密钥笔记出题。第一步可能提出下面的调用。它是教学示例，省略了完整 API 外层字段：

```json
{
  "id": "call_s1",
  "type": "function",
  "function": {
    "name": "search_notes",
    "arguments": "{\"query\":\"API 密钥环境变量\",\"top_k\":3}"
  }
}
```

`name` 是工具名；`arguments` 是装着 JSON 的字符串；`id` 是这次请求的编号。模型可以提出它，但此时磁盘还没有因为这条消息被读取。

本地程序解析参数，只允许已登记的 `search_notes` 和 `read_note`。搜索返回笔记 ID、标题、行号、摘要；下一次读取请求使用 `01-API配置.md` 的第 1–8 行。原文包含“API 密钥用于认证调用方，建议放在本地环境变量中。”

再下一轮可以生成：“API 密钥建议保存在哪里？”答案是“本地环境变量”，并带上逐字引文。最终内容来自模型或预写响应，真实读取则来自本地函数；两个来源不能混淆。

## 每一步的输入输出

| 步骤 | 输入 | 输出 |
| --- | --- | --- |
| 告知工具 | 任务、工具说明、参数规则 | 模型可见的能力清单 |
| 提出请求 | 当前会话 | 工具名、参数字符串、调用 ID |
| 检查执行 | 请求与允许清单 | 成功数据或错误 |
| 回传结果 | 调用 ID、执行结果 | 一条 tool 消息 |
| 再次请求 | 含工具结果的会话 | 新调用或最终题目 |

一次调用并不等于一次完整任务；本库成功演示需要搜索和读取两次工具执行。

## 常见疑问

**普通 JSON 和工具调用有什么区别？**普通 JSON 可以只是在描述一件事。工具调用还需要应用识别协议、匹配函数、执行并回传结果；没有这段执行逻辑，JSON 不会自动产生行动。

**模型输出一段 Python 就会运行吗？**本项目不会。它只匹配两个固定工具名，没有 `eval` 或任意 Shell 执行入口。

**一定要装框架或 SDK 吗？**不用。这里用 Python 标准库组织循环和 HTTP 请求，先看清机制。厂商之间字段和支持范围可能不同，迁移时需要适配。

## 小练习与自测

**题目：**模型写“我已经查看笔记”，轨迹却只有搜索，没有成功读取，能接受最终引文吗？

**参考答案：**不能。当前最终校验只接受成功 `read_note` 返回文字中的引文，搜索摘要不会加入已读依据集合。

**纸上练习：**写出 `search_notes` 的输入和输出，再标出谁执行它。答案应包括关键词、数量参数以及笔记候选；执行者是本地程序。
