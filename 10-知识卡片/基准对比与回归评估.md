# 基准对比与回归评估

[卡片目录](README.md) · [第五阶段课程](../20-课程笔记/第五阶段-评估与部署课程及实践顺序.md)

## 一句话解释

**基准是改动前的可核对记录；回归评估是在可比较条件下，检查修改有没有让已有表现退步。**像换复习方法后，既看进步的题，也看原先会做而现在做错的题。

## 为什么需要它

只展示改进后的一次好结果，无法证明比之前好。资料、代码和题集同时变了，也难以知道是哪项造成变化。

先保存基准，尽量一次改变一个因素。除了总分，还要保留逐题结果、耗时与失败；平均分上升可能掩盖重要题变差。

## 用 MindVault 走一遍

本库先用 K=1 检索，再在同一代码、资料、题集和切分下改成 K=3。K 是最多返回的片段数，不是答案数量。

如果一题同时需要 API 配置和 JSON 核对两份笔记，只找到第一份：

| 指标 | 算法 | 这一题的值 |
| --- | --- | --- |
| 来源命中 | 至少找到一个目标文件 | 1 |
| 来源覆盖 | 找到目标文件数 / 需要文件数 | 1/2 |
| 原句覆盖 | 完整包含目标原句的条目数 / 目标条目数 | 假设仅第一句完整出现，则 1/2 |

dev 有四道有依据题。假设前三题覆盖为 1，多来源题为 0.5，平均为 `(1+1+1+0.5)/4=0.875`，即 87.5%。来源命中率 1 与来源覆盖 0.875 可以同时成立。

资料外题单独统计无候选率：没有返回片段的资料外题数 / 资料外题总数。它不参加上述有依据题的分母，也不是模型拒答率。

比较器算候选减基准。0.875 到 1 的差为 0.125，即增加 12.5 个百分点，不是相对增加 12.5%。自动条件通过表示这些汇总指标没有退步，且适用的预写行为检查通过，仍需人工评审。

## 每一步的输入输出

| 步骤 | 输入 | 输出 |
| --- | --- | --- |
| 保存基准 | 固定条件、K=1 | 第一份 report.json |
| 运行候选 | 同条件，仅改 K=3 | 第二份 report.json |
| 检查可比性 | Python、摘要、切分等 | 可比或明确拒绝 |
| 计算变化 | 指标与逐题结果 | 差值、遗漏与改善案例 |
| 做决定 | 自动证据、人工质量和成本 | 接受、继续改进或保留旧方案 |

原句须完整出现在某个对应片段才计覆盖；分散在两段里由人拼起来，不自动算当前脚本的原句命中。

## 常见疑问

**K 越大越好吗？**可能补全来源，也可能增加无关资料、上下文与生成成本。检索报告不能证明生成效果也变好。

**自动通过能说明每一道题都没退步吗？**不能。比较器检查汇总指标，一题变差可能被另一题改善抵消，逐题仍要看。

**改了代码后为什么比较器拒绝？**compare 只演示同一代码改变 K。代码摘要不同，就不是这个实验。跨版本评估应另设计对照，不能删检查来假装条件相同。

**反向比较有什么用？**把原候选当基准，可以练习识别指标下降。结果取决于数据，不能只凭版本名判断。

## 小练习与自测

**题目：**三道有依据题的来源覆盖分别 1、0.5、0，平均多少？

**参考答案：**`(1+0.5+0)/3=0.5`，这是按题平均，不是合并所有文件后再算。

**题目：**检索改善，生成答案却更爱引用无关段落，能宣布全面改善吗？

**参考答案：**分别报告检索改善和生成问题，继续人工答案与引用评审。
