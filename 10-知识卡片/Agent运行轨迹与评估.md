# Agent 运行轨迹与评估

[卡片目录](README.md) · [第四阶段课程](../20-课程笔记/第四阶段-工具调用与Agent课程及实践顺序.md)

## 一句话解释

**运行轨迹记录实际请求、行动、结果与停止原因；评估判断这些行动和最终作品是否满足任务。**像做实验要同时看步骤记录和实验结果。

## 本项目需要看什么

| 层次 | 要问的问题 |
| --- | --- |
| 任务 | 是否生成需要的复习题？是否遗漏用户要求？ |
| 工具 | 选对工具了吗？参数正确吗？是否重复无效调用？ |
| 依据 | 实际读到了支持答案的笔记吗？引文是否支持结论？ |
| 执行 | 是否正常结束？请求数、工具次数与耗时是多少？ |
| 成本 | 哪几次是真实请求？有无实际 usage，是否核对账单？ |

这里记录可观察事件，不需要索取或保存模型的隐藏推理全文。调用记录能证明工具做了什么，不能完整证明模型为什么做这个选择。

Anthropic 的 Agent 设计文章强调从简单实现开始并观察任务表现；LangGraph 教程提供可检查的工作流结构。[设计参考](https://www.anthropic.com/research/building-effective-agents) · [框架参考](https://docs.langchain.com/oss/python/langgraph/workflows-agents)

## 用同一组任务比较

保留正常任务、无答案、参数错误、重复调用、资料注入等场景。先记基准，再只改工具描述或一个预算，用相同任务对照。固定脚本通过，只能证明循环能处理这个预设情节。

## 小练习与自测

- [ ] 找到一次失败发生在工具前、工具内还是最终内容检查。
- [ ] 人工判断一条复习题的答案与引文是否一致。

**问题：**最终输出看起来不错，还需要轨迹吗？

**参考要点：**需要；可能碰巧答对却没读取资料，也可能做了多余或失败的动作。
