# 适配器保存与基座兼容

[卡片目录](README.md) · [进阶课程](../20-课程笔记/进阶阶段-模型原理本地部署与微调.md)

## 一句话解释

**LoRA 适配器通常保存增量参数，重载时还要匹配基座、目标层、Tokenizer 与运行条件。**像给特定版本书页贴批注，不能换一本排版不同的书还默认贴得对。

## 为什么需要它

训练完成不等于得到一个可随意复制执行的完整模型。如果只保存适配器而忘了基座版本，之后可能加载失败，或虽然能运行却行为不同。

保存必要信息并实际重载，是验证训练产物可用的最后一步；文件存在和文件可信、行为正确又是不同检查。

## 用 MindVault 走一遍

本库两种适配器有明确区别：

| 产物 | 内容 | 需要配什么 |
| --- | --- | --- |
| 玩具 adapter.json | 两个列表、单位矩阵基座与格式标识 | toy_lora.py 的二维线性实验 |
| PEFT adapter 目录 | LoRA 配置与增量权重 | 兼容的 HF 基座及 PEFT |
| tokenizer 目录 | 词表、特殊标记和模板等 | 相应模型的编码流程 |
| run.json | 基座、revision、数据与依赖摘要、设置 | 本次可复现记录 |

真实选修基座是 Qwen/Qwen2.5-0.5B-Instruct，revision 固定为 `7ae557604adf67be50417f59c2c2f167def9a775`。revision 可理解为仓库内容的具体版本标识，比“最新”明确。

训练保存 adapter_config.json、adapter_model.safetensors 等产物；run.json 另记录这些文件及 Tokenizer 文件的摘要。evaluate 先检查基座、revision、数据摘要和产物，再核对依赖与 max_length，加载同一基座做前后对照。

当前 evaluate 重新从固定基座 revision 加载 Tokenizer；保存的 tokenizer 目录供复现与检查，不表示代码改用它重新训练了词表。若将来训练时新增 Token 或改变词表，还需要检查嵌入层等兼容与保存方式，当前未实现这类扩展。

合并适配器可把增量加进兼容权重，但转格式、量化、导入推理引擎是另一些步骤。把文件改名为 GGUF 不会完成格式转换；当前玩具、HF 和 Ollama 三条路径不能直接互换产物。

## 每一步的输入输出

| 步骤 | 输入 | 输出 |
| --- | --- | --- |
| 保存 | 适配参数与配置 | adapter 目录 |
| 记录环境 | 基座版本、模板、依赖与数据 | run.json 和文件摘要 |
| 校验 | 实际文件与记录 | 完整性和条件一致检查 |
| 重载 | 兼容基座、适配器 | 适配后的模型 |
| 同题比较 | 相同问题与解码设置 | 基座/适配回答及人工评审 |

适配器配置描述如何把增量接入模型；权重文件存实际学到的数值。两者作用不同，不能只留其中一个。

## 常见疑问

**同系列同参数量就一定兼容吗？**不保证，结构、层名、权重版本和模板都可能不同。以具体标识和配置核对。

**摘要通过就证明没有恶意或质量良好吗？**不是。它证明与记录一致；不带可信认证的摘要不能独自证明来源和安全，也不评答案。

**保存了适配器就能断点续训吗？**本库只保存最终适配器，没有完整优化器和训练进度恢复逻辑，不能当作精确续训检查点。

**适配器很小，别人不用下载基座吗？**通常仍要有兼容基座，并遵守其使用条件。小文件不包含完整通用能力。

**哪里保存实验产物？**留在 .local，笔记复盘保存摘要和结论。不要把权重、环境和大缓存加入学习仓库。

## 小练习与自测

**题目：**玩具 adapter.json 写了 rank=1，能放进 PEFT 的真实模型吗？

**参考答案：**不能。格式、矩阵维度、目标层与基座都不相同，rank 只是其中一个条件。

**练习：**先重载玩具适配器比较同一输入；有真实训练产物后，再核对配置、权重、版本记录和同题输出，不只检查文件是否生成。
