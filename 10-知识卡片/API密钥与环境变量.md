# API 密钥与环境变量

[卡片目录](README.md) · [课程入口](../20-课程笔记/第二阶段-模型API课程与实践顺序.md)

## 一句话解释

**API Key 是证明调用权限的凭据；环境变量是进程读取配置的一种方式。**密钥像门禁卡，变量名像“放门禁卡的栏目名”，写出栏目名不等于已经有有效凭据。

## 为什么需要它

程序需要认证值，知识笔记只需要记录配置名称和使用方法。把真实值写进代码、普通 Markdown 或输出记录，会随复制和 Git 历史传播。

环境变量减少把凭据写死在源码的需要，但不是绝对保密保险；仍要避免打印、截图和把整个进程环境保存进日志。

## 用 MindVault 走一遍

本项目只在 live 分支读取 DEEPSEEK_API_KEY，并放入 Authorization 请求头；preview/mock 不读这个密钥，也不发模型请求。

下面的 Python 例子只显示配置状态，不显示真实值：

```python
import os

api_key = os.environ.get("DEEPSEEK_API_KEY", "").strip()
print("已设置密钥" if api_key else "尚未设置密钥")
```

有值不代表认证一定有效，还要看真实服务响应。空值在本地就拒绝；无效值可能返回认证错误。

| 内容 | 能否写在学习笔记 | 原因 |
| --- | --- | --- |
| DEEPSEEK_API_KEY 名称 | 可以 | 只是配置约定 |
| 如何从环境读取 | 可以 | 程序逻辑 |
| 真实凭据 | 应放本地凭据配置 | 有调用权限和费用风险 |
| 请求模式和用量 | 可按需要记录 | 便于复盘，先检查内容 |

实践一用 Read-Host 安全交互输入，再给当前 PowerShell 会话的环境变量赋值。启动的 Python 会继承该进程环境；新开终端不一定有相同值。脚本不会自动加载 .env 文件，写了 .env 不等于已经配置成功。

测试完按实践步骤清理当前会话变量。不要把真实值发给我“帮忙检查”，状态和错误码通常足够先定位配置问题。

## 每一步的输入输出

| 步骤 | 输入 | 输出 |
| --- | --- | --- |
| 准备凭据 | 自己的服务账户 | 可用 Key |
| 本地设置 | 交互输入和变量名 | 当前进程配置 |
| 程序读取 | 环境变量 | 内存中的认证值 |
| 发送认证 | HTTPS 请求头 | 服务认证结果 |
| 记录实验 | 模式、错误、用量 | 不含密钥的复盘 |

模型任务消息不需要包含 Key；把密钥贴在正文里不构成正确认证。

## 常见疑问

**私有仓库可以保存真实 Key 吗？**仍应分离，私有设置不消除历史、误分享或后续复制。

**.gitignore 能防止所有泄漏吗？**不能，已跟踪文件和把值写进普通笔记等情况仍可能入库。已泄漏应在服务端撤销或轮换，不能只删除本地那一行就当解决。

**DEEPSEEK_MODEL 也是密钥吗？**它是可选模型配置。当前默认可从环境读取模型名，但与认证值不同。

**密钥存在却 401 怎么办？**核对账户、实际变量和服务文档，不通过连续重试解决错误凭据。

**设置当前终端变量会修改所有已运行应用吗？**不会自动追溯改变已有进程，应确认真正发请求的进程拿到配置。
