# 技术方案与 AI 扩展

[返回首页](../README.md)

## 当前分工

| 组成 | 职责 | 选用原因 |
| --- | --- | --- |
| Obsidian | 编辑、阅读、搜索和关联笔记 | 适合每天使用，文件保存到本地 |
| Markdown | 知识内容的保存格式 | 可读、可迁移，便于程序处理 |
| Git | 修改历史 | 方便追踪变化、找回旧版本 |
| GitHub 私有仓库 | 远端存储和跨电脑使用 | 私有积累，以后可挑选内容分享 |
| GitHub Desktop（可选） | 通过按钮执行 Git 操作 | 减少命令行操作 |

目前笔记层没有部署网站、数据库、常驻模型服务或自动同步任务。项目实践区已有可按步骤启动的教学实验，包括 RAG、Agent 与本机检索服务；它们不等于已经为整个笔记库启用日常 AI 助手。基础记录和 GitHub 仓库存储可以使用免费方案。

## 为什么现在这样搭

先让记录、整理、复习和实践形成习惯。Markdown 文件既可以在 Obsidian 使用，也可以交给未来的应用读取。使用通用 Markdown 链接，便于在 GitHub 和其他工具中阅读。

来源、自己的理解、验证结果和待解决问题分开记录，可以帮助未来的 AI 问答找到依据，也能保留知识的适用范围。

## 以后接入 AI 的三种方式

### 1. 辅助整理单篇笔记

选中一篇或几篇笔记，让 AI 总结、出题或整理成知识卡片。先检查生成内容，再写回仓库。接入插件或工具时单独选择要提供给模型的笔记范围。

### 2. 基于整个知识库的问答

流程是：读取指定笔记 → 切分与建立索引 → 按问题检索相关片段 → 交给模型回答 → 返回笔记文件与依据。

这通常称为 RAG。[项目 03](../30-项目实践/03-RAG知识库问答/README.md) 已提供基于示例资料的检索与问答实验，[项目 05](../30-项目实践/05-评估与本地部署/README.md) 提供本机检索服务。若要用于整个 MindVault，还需要明确可读取的笔记范围、配置索引与模型，并选择日常使用入口；这些整库集成目前尚未配置。私有仓库不会自动被模型读取。

现成工具可参考 [Khoj 官方文档](https://docs.khoj.dev/)，其支持 Markdown 与 Obsidian。若以后自己实现，也可以继续读取当前目录中的文件。

建议把可重建的向量索引保存在已忽略的 `.local/` 或 `.cache/` 目录，模型密钥保存在本地环境配置中。云端模型可能产生调用费用，并会接收发送给它的笔记片段；本地模型则需要相应的硬件和运行环境。

### 3. 生成可分享的知识网站

以后可以从适合公开的笔记生成网站，例如使用 [Quartz](https://quartz.jzhao.xyz/)。发布前挑选内容，并单独确定网站访问权限；私有 GitHub 仓库并不代表发布的网站也会私有。

## 什么情况下再升级

- 经常找不到学过的内容：增加语义检索或知识问答。
- 需要反复整理资料：尝试 AI 辅助整理。
- 希望分享成果：增加网站展示。
- 手动同步成为负担：再考虑 Obsidian Git 插件等自动化方式。

这些扩展可以逐步增加，不需要先更换笔记格式。
