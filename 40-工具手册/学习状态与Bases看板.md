# 学习状态与 Bases 看板

[打开学习看板](../学习看板.base) · [学习总导航](../学习总导航.md) · [学习地图](../学习地图.md) · [工具手册](README.md)

## 每天从哪里开始

在 Obsidian 按 `Ctrl+O`，搜索“学习看板”，打开根目录的 `学习看板.base`。默认是“待学习”视图，按学习阶段分组；点击左上方的视图名称，可以切换“待实践”“进行中”“状态看板”“待整理”“已完成”和“全部学习笔记”。

点击“笔记”列中的链接即可打开正文。项目说明文件虽然叫 README，看板会显示各项目的完整标题，便于区分。

| 视图 | 什么时候用 |
| --- | --- |
| 待学习 | 找下一张卡片或下一份课程指南 |
| 待实践 | 找待动手的项目、待验证的阅读结论 |
| 进行中 | 接着读或接着做上次开始的内容 |
| 状态看板 | 按状态列总览任务，拖动卡片调整进度 |
| 待整理 | 处理收集箱里尚未分类或提炼的内容 |
| 已完成 | 回顾有学习或实践证据的笔记 |
| 全部学习笔记 | 按阶段查看全部条目，检查状态是否写对 |

需要专注某阶段时，可在视图的筛选菜单中为“当前视图”增加 `stage` 条件。`stage` 为文本，使用 `01 基础与Python` 到 `06 进阶`；`00 学习方法` 和 `00 未分类` 用于方法类和待分类笔记。

## 统一的六种状态

所有学习笔记使用同一个 `status` 字段，属性值请按下面的写法填写。

| 状态 | 含义 | 什么时候进入下一步 |
| --- | --- | --- |
| 待整理 | 已收集，但还未确定主题或整理方式 | 完成归类、保留来源并明确学习目标后，改为待学习或待实践 |
| 待学习 | 材料已准备，还没有开始自己学习 | 开始阅读、自测或理解时改为学习中 |
| 学习中 | 正在理解、阅读、自测或写复盘 | 有待动手验证的内容时改为待实践；纯概念内容达到自己的验收要求后可改为已完成 |
| 待实践 | 实践任务已准备，或理解后还需要验证 | 自己开始运行、修改输入或做实验时改为实践中 |
| 实践中 | 正在动手、排错或检查结果 | 留下结果与限制，满足本次明确的验收范围后改为已完成 |
| 已完成 | 本次学习目标已验收，并保留解释、例子、自测或实践证据 | 发现遗漏或需要复习时，可回到学习中或待实践 |

不要求每篇笔记走遍六种状态。新项目可以直接从待实践开始；纯概念卡片可以在自测和个人例子完成后结束。已完成表示这篇笔记的本次目标已完成，不能据此推断所有选修实验或整个主题都已掌握。

卡片和项目各自记录状态。完成一张卡片不会自动完成整个项目；[学习地图](../学习地图.md)里的细分复选框仍需按实际情况更新，两者没有自动勾选联动。

## 怎样修改状态

1. 在表格视图中编辑“学习状态”单元格，输入上表中的一个值；也可以打开笔记，在顶部属性中修改 `status`。
2. “状态看板”视图按状态分列，拖动卡片会修改该笔记的状态。学习完成后再操作，不需要为了看板整齐而提前移动。
3. 在正文记下自己的理解、例子或实验结果。状态不会代替这些证据。
4. 返回对应视图，条目会按新状态重新筛选。文件自动保存到本地；需要同步时说“帮我提交 MindVault”。

例如：打开“大模型”卡片 → 改为学习中 → 阅读并自己解释 → 完成自测、补一个例子 → 根据验收结果改为已完成或待实践。

## 新笔记如何出现在看板里

使用[模板](../80-模板/README.md)新建笔记，保留这些属性即可：

```yaml
status: 待学习
type: 知识卡片
stage: 01 基础与Python
```

`type` 描述笔记类型，例如知识卡片、课程笔记、阅读笔记、项目实践、学习复盘、收集笔记。新模板的阶段默认为 `00 未分类`，创建后再选合适阶段。可选的 `title` 用于展示更友好的标题，项目 README 已设置此字段。

看板包含 `00-收集箱`、`10-知识卡片`、`20-课程笔记`、`30-项目实践`、`50-学习复盘` 中具有非空 `status` 的 Markdown 文件。模板目录、附件、工具手册、根目录导航和本地缓存不进入结果。

当前项目以各项目 README 作为进度入口。实践步骤、评估记录模板和运行检查记录不单独设置状态，避免把一个项目拆成多份待实践任务；项目内部步骤从 README 进入。以后新建自己的独立实验笔记，使用项目实践模板即可单独追踪。

## 使用条件与参考

本机 Obsidian 为 1.14.5，Bases 核心插件已启用。表格视图适用于支持 Bases 的版本，原生状态看板需要 Obsidian 1.14 或更高版本。另一台电脑若看不到 Bases，请在核心插件中启用；这些界面设置不随本次 Git 提交同步。

GitHub 可以保存和查看 `.base` 的配置文本；交互看板在 Obsidian 中打开。看板没有复制笔记内容，编辑状态会直接写回对应 Markdown 文件的属性。
