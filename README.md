# MindVault · AI 学习知识库

**从基础概念到可运行的小项目，用知识卡片、实践代码和学习复盘，搭建自己的 AI 学习体系。**

MindVault 是面向 AI 入门与应用开发的个人学习知识库，使用 **Markdown + Obsidian + GitHub** 管理内容。学习主线覆盖 Python 基础、模型 API、RAG、工具调用与 Agent、评估与部署，并提供模型原理、本地推理与微调选修。

目前包含 **68 张知识卡片、6 份课程指南、6 个项目、16 个实践入口**。核心概念在库内给出通俗解释、完整例子、输入输出、自测与参考答案，外部教程用于溯源和深入阅读。

仓库：[Bindy-lbb/MindVault](https://github.com/Bindy-lbb/MindVault)（公开）

**快速入口：**[学习总导航](学习总导航.md) · [个人学习地图](学习地图.md) · [知识卡片](10-知识卡片/README.md) · [项目实践](30-项目实践/README.md) · [学习看板说明](40-工具手册/学习状态与Bases看板.md)

## 适合怎样使用

- 刚开始学习 AI：按阶段理解概念，读一组卡片，再完成一个小练习。
- 希望用项目学应用开发：从读取笔记出发，逐步实现 API 调用、检索、工具执行和本机服务。
- 希望积累自己的知识：把文章、疑问和实践结果整理成可关联、可搜索、可追踪修改的笔记。

每张卡片尽量回答“是什么、为什么需要、怎样在 MindVault 使用、如何确认自己理解了”。实践区同时保留成功路径、错误示例和验收方法；资料准备情况与个人学习完成状态分别记录。

## 从这里开始

每日入口：[Bases 学习看板](学习看板.base) · [看板与状态说明](40-工具手册/学习状态与Bases看板.md)。查看待学习、待实践和进行中的笔记，更新自己的学习进度。

1. 阅读 [Obsidian 使用指南](40-工具手册/Obsidian使用指南.md)，把这个文件夹作为仓库打开。
2. 填写 [我的 AI 学习地图](学习地图.md)，选一个近期想解决的问题。
3. 打开 [AI 学习总导航](学习总导航.md)，按“知识卡片 → 实践步骤 → 验收记录”的顺序开始学习。
4. 打开 [我的第一篇学习笔记](00-收集箱/我的第一篇学习笔记.md)，记录今天的收获。
5. 学习结束后，可以对我说“帮我提交 MindVault”，或按 [GitHub 同步指南](40-工具手册/GitHub同步指南.md) 提交并推送。

已有本地文件夹时，直接用 Obsidian 打开 `E:\my-projects\MindVault`。首次使用或换电脑时，先克隆仓库，再把克隆后的文件夹作为 Obsidian 仓库打开。GitHub 可以直接阅读 Markdown；`.base` 学习看板在 Obsidian 中使用。

```sh
git clone https://github.com/Bindy-lbb/MindVault.git
```

运行代码前先看[实践运行约定与排错](40-工具手册/实践运行约定与排错.md)。主线各阶段都有无需模型账户的入门操作；真实 API 调用需要自行配置账户与密钥，语义检索、本地模型和真实微调选修还需要相应依赖或模型文件。

## 日常使用习惯

每天从[学习总导航](学习总导航.md)找到下一组卡片和实践，在[学习地图](学习地图.md)记录个人目标与完成进度。总导航包含基础、API、RAG、Agent、评估与部署，以及原理、本地模型和微调选修。

- 学习前：拉取 GitHub 更新。
- 学习时：先记录到收集箱；理解清楚后，再整理成知识卡片或项目记录。
- 每篇笔记保留来源、自己的理解、实践结果和疑问。
- 学习后：提交并推送到 GitHub。Obsidian 保存文件不会自动上传。
- 定期回顾收集箱，把有价值的内容整理到对应目录。

## 当前方案与后续扩展

| 组成 | 在项目中的作用 |
| --- | --- |
| Markdown | 保存知识卡片、学习路线、实践步骤和复盘，方便迁移与程序读取 |
| Obsidian 与 Bases | 本地阅读、编辑、关联笔记，按学习状态查看内容 |
| Git 与 GitHub 公开仓库 | 保存修改历史、备份与分享内容，按需提交并同步 |
| Python | 运行配套示例；基础路径以标准库实验为主，选修按项目配置依赖 |

笔记阅读与管理不依赖数据库或常驻服务器。配套代码已提供 RAG、Agent、评估和本机检索服务等教学实验，默认从明确的示例资料开始；整个知识库的常驻 AI 问答、自动写回、网站展示和自动 Git 同步尚未配置。`mock`、`fixture`、`scripted` 等模拟结果会明确标注，真实模型效果需要实际运行后记录。

后续可以逐步接入指定笔记范围的 RAG 问答、AI 辅助整理或知识网站，继续复用现有 Markdown 内容。详见[技术方案与 AI 扩展](40-工具手册/技术方案与AI扩展.md)。

## 内容维护与来源

新增材料先进入收集箱，再整理为知识卡片或实践记录；保留原始来源，用自己的话解释，并记录适用条件和实际验证结果。模板见[模板说明](80-模板/README.md)，最近一次全库检查见[检查记录](50-学习复盘/MindVault全库检查-2026-10-29.md)。

模型凭据、运行输出、索引和本地依赖按项目约定保存在本地，不随笔记提交。引用的教程、文档与第三方代码，其权利和使用条件以原始来源为准。
