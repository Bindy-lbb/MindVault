# 实践三：发布包、重启与回滚

[项目入口](README.md) · [上一项](实践二-本地服务与健康检查.md)

本练习只创建本地新目录，不上传云端、不创建 GitHub Release。先按实践一检查评估，再保存明确版本。

## 1. 打包并核对

从仓库根目录执行：

```powershell
$stage5 = '.\30-项目实践\05-评估与本地部署'
python "$stage5\release.py" package --output '.local/releases/mindvault-0.1.0' --version 0.1.0
python "$stage5\release.py" verify --output '.local/releases/mindvault-0.1.0'
```

默认包里有：local_service.py、rag_practice.py、service.json、START.md、五篇选定示例，以及 RELEASE.json 清单。清单列出 9 个文件的 SHA-256，不包含自己。运行数据留在包内 `.local/`，校验时允许该目录变化。

没有复制 API Key、Git 历史、日志、依赖环境或旧索引。核对文件摘要只能发现与清单不一致，清单本身不是签名或安全认证；只运行自己信任来源的代码。

## 2. 在最终目录建立索引并运行

先把包放到打算保留的位置；默认输出目录就可作为最终位置。在另一个终端：

```powershell
Set-Location 'E:\my-projects\MindVault\.local\releases\mindvault-0.1.0'
python local_service.py index --config service.json
python local_service.py serve --config service.json
```

索引含绝对资料路径，移动到其他位置后要使用新索引名重建，不复制旧索引。发布包核心只需可用 Python，不需要项目 02/04、模型权重或第三方依赖。

不切换目录也能用完整路径启动，配置仍按它所在位置解析。检查 `/ready` 和同一条 `/search`，停止后重启，确认原索引可重载。

## 3. 保留旧版，做一次恢复演练

另建 `mindvault-0.2.0`，不要覆盖 0.1.0：

```powershell
Set-Location 'E:\my-projects\MindVault'
python "$stage5\release.py" package --output '.local/releases/mindvault-0.2.0' --version 0.2.0
```

在 **0.2.0 实验包**的一篇笔记末尾加一行，再 verify，预期摘要不符。保留这份失败记录；停止新版本后重新启动 0.1.0，检查 ready 和原来的问题。

这是本地文件版本与运行恢复演练，没有数据库迁移、外部写入或流量切换。真正改变业务代码后，还要重新评估，不仅检查文件摘要。

## 4. 记录环境与发布决定

记录 `python --version`、Git 提交、发布清单、配置、评估报告和人工核对。当前核心无第三方依赖；以后安装依赖时参考[pip 可重复安装](https://pip.pypa.io/en/stable/topics/repeatable-installs/)，在独立环境测试后记录版本，别直接复制 .venv。

自动比较通过、Git 提交成功与应用可用是不同证据。先确定本机使用是否足够，再考虑远程访问。

## 5. 云部署选修读什么

需要网页时参考 Datawhale 第 4 章与[Streamlit 部署准备](https://docs.streamlit.io/deploy/streamlit-community-cloud/deploy-your-app)，需要 API 服务时参考[FastAPI 部署概念](https://fastapi.tiangolo.com/deployment/concepts/)。当前包不是 Streamlit 应用，需另做入口与部署配置；也不能把本机 http.server 直接开放到公网当生产方案。

先用可公开的自写示例和单独应用目录，核对平台访问权限、密钥管理、数据范围、运行限制和费用，再实际部署。MindVault 私有仓库不在本练习中公开，也没有创建收费资源。

- [ ] 能重新运行保留的旧版并验证同一问题。
