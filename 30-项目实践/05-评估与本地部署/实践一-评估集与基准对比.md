# 实践一：评估集与基准对比

[项目入口](README.md) · [下一项](实践二-本地服务与健康检查.md)

目标：固定问题和依据，再改一个参数观察差异。默认只跑 dev，不用模型 Key、不安装第三方依赖。

运行前可看[统一运行约定与排错](../../40-工具手册/实践运行约定与排错.md)：从仓库根目录开始，首次代码块设置会话变量；新终端需重新设置。输出使用新名称，预期失败不记作成功。

## 1. 先看标签

打开[题集](examples/eval_cases.json)。每题有 id、split、question、expected；expected 的 path 相对资料目录，quote 为人工挑出的原句，资料外题为空数组。脚本会确认原句仍在资料中，防止把过期标签直接当真值。

dev 有 4 道有依据题（含 1 道双来源题）、1 道资料外题；holdout 留 2 道有依据题和 1 道资料不足题。例子公开且很小，只用于学习划分方法，不能冒充独立真实用户测试集。

## 2. 跑基准与候选

```powershell
Set-Location 'E:\my-projects\MindVault'
$env:PYTHONUTF8 = '1'
$stage5 = '.\30-项目实践\05-评估与本地部署'
python "$stage5\evaluate.py" run --top-k 1 --output '.local/eval/k1-v1'
python "$stage5\evaluate.py" run --top-k 3 --output '.local/eval/k3-v1'
python "$stage5\evaluate.py" compare --baseline '.local/eval/k1-v1/report.json' --candidate '.local/eval/k3-v1/report.json' --output '.local/eval/compare-v1'
```

每份 run 结果有 report.json 和 review.md。比较器只允许相同题集、资料、代码、Python 与切分改变 K；不符合时先说明条件变化，再重新设计对照，不伪装单变量实验。

## 3. 读四个指标

- 来源 Hit@K：有依据题中，至少找到一个目标文件的比例。
- 来源 Recall@K：每题找到的目标文件数 / 所需文件数，再对有依据题平均。
- 原句覆盖：每题的目标原句被对应检索片段完整包含的比例，再平均。跨片段拼合不自动算命中。
- 资料外无候选率：资料外题中没有返回候选的比例；这是检索行为，不是模型拒答率。

预期小样例：K=1 的命中率为 1，但来源/原句覆盖为 0.875；K=3 覆盖为 1。原因是多来源题 K=1 只能取一段。比较通过仅表示这些自动条件没有退步，不能说明真实生成答案完全正确。

报告还记录四个预写 Agent 情节的次数和停止行为。它们是回归样例，真实 API 请求为 0，usage 为 null。检索耗时不含模型生成，少量样本的 P95 只用于学习记录方法。

## 4. 补人工评审

用项目 03 或 04 的 live 结果填写 review.md：答案是否正确、引文是否支持、该不该拒答、哪些要求遗漏。尚未调用真实模型就写“未实测”，不要把空评分当成 0 分或 100 分。

改工具描述、提示词、模型或代码时，另记录版本与比较方法；当前 compare 只演示相同代码改变 K。

## 5. 留到最后再跑 holdout

```powershell
python "$stage5\evaluate.py" run --split holdout --top-k 3 --output '.local/eval/holdout-v1'
```

同义改写可能被关键词漏掉；带 Token 字样但询问真实余额的问题可能仍检索到片段，却没有答案。保留这些失败，别把 holdout 每次都用来调参。此次自动整理没有运行这组保留题。

自建题集时使用 `--cases` 与 `--corpus`；非默认资料会跳过固定 Agent 情节，避免用不配套的原文验证预写答案。

- [ ] 能解释格式、检索、生成和人工评分的区别。
