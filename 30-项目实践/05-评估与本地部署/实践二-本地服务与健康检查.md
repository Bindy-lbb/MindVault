# 实践二：本地服务与健康检查

[项目入口](README.md) · [上一项](实践一-评估集与基准对比.md) · [下一项](实践三-发布包重启与回滚.md)

这是本机关键词检索服务，不调用模型、不公开网站。先准备一个终端运行服务，再开另一个终端发请求。

## 1. 核对配置并建库

从仓库根目录执行：

```powershell
$env:PYTHONUTF8 = '1'
$stage5 = '.\30-项目实践\05-评估与本地部署'
python "$stage5\local_service.py" index --config "$stage5\service.example.json"
```

[示例配置](service.example.json)中的相对路径按配置文件所在目录解释。资料指向第三阶段五篇示例；索引和日志在**项目 05 内部**的 `.local/service/`，已被 Git 忽略，不是仓库根目录同名目录。

已有索引不会覆盖。重复练习直接启动；资料或切分改变时，在新配置里使用新的 index 文件名，重新建库。复制配置到其他目录后，记得核对其中相对路径。

## 2. 启动并保持终端运行

```powershell
python "$stage5\local_service.py" serve --config "$stage5\service.example.json"
```

终端应显示 `http://127.0.0.1:8765/health`。端口被占用时可临时用 `--port 8766`，然后把后续请求端口也换成 8766；不要随意终止其他程序。服务地址固定回环，没有外网监听参数。

## 3. 在第二个终端发请求

```powershell
Invoke-RestMethod -Uri 'http://127.0.0.1:8765/health'
Invoke-RestMethod -Uri 'http://127.0.0.1:8765/ready'
$encodedQuestion = [uri]::EscapeDataString('API 密钥放在哪里？')
Invoke-RestMethod -Uri ('http://127.0.0.1:8765/search?q=' + $encodedQuestion + '&k=3')
```

health 检查进程响应；ready 检查索引与资料一致；search 返回原文、文件名、标题、行号与 request_id。它是检索摘录，不是模型生成的答案。空命中仍是 200；问题缺失、重复参数或 K 超范围返回 400；索引不可用返回 503。

只支持 GET 这三个接口，没有任意文件下载、目录列表或文件写入接口。发布前仍不能把教学 HTTP 服务当作已具备认证和生产能力。

## 4. 观察日志与失败

打开配置 log 指向的 events.jsonl，用 request_id 对照响应。日志包含路由、状态、耗时和命中数量，不包含 q、原文或请求头。

试 `search` 不带 q，观察 invalid_query；再查询“土星光环倾角”，观察正常空数组。两种情况不混为“没有答案”。

如果要测试资料改变，先把一篇示例复制到自己的 `.local/service-notes/`，使用指向该副本的新配置和索引。启动后修改副本，预期 health 仍 200、ready/search 503。停止服务，换新索引名重建，再启动核对更新内容。

## 5. 停止与重启

回到服务终端按 Ctrl+C。再执行同一条 serve，索引不必重复建立；查询相同问题检查结果。终端关闭时服务不会自动保持运行，本项目没有设置开机启动或自动重启任务。

## 验收

- [ ] 三个接口能解释各自意义，能回到检索原文。
- [ ] 按 request_id 找到元数据日志，并确认没有问题正文。
- [ ] 分清参数错误、正常无命中和索引过期。
- [ ] 停止后再启动，功能仍可使用。
