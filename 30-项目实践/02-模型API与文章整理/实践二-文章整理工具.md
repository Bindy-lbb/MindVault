# 实践二：文章整理工具

[项目首页](README.md) · [实践一](实践一-首次API调用.md)

## 第一步：读样文与约定格式

打开 [示例文章](examples/示例文章.md)和 [模拟整理结果](examples/模拟整理结果.json)。正文为本库自拟，结果为人工准备的教学数据。

四个字段分别是摘要、原文观点与依据、待研究问题、额外建议。确认观点和建议的区别，再看程序怎样校验它们。

## 第二步：离线生成一份草稿

从 MindVault 根目录执行：

```powershell
python '.\30-项目实践\02-模型API与文章整理\model_api.py' summarize --mode mock --output '.\.local\stage2\article-mock-01.md'
```

打开草稿，核对模式标记、原文文件名、两条依据及调用记录。`mock` 只接受与配套样文相同的正文；换其他文章时不会冒充已经理解了新文章。

## 第三步：准备自己的正文

把一篇你熟悉的短文保存为 UTF-8 文本，例如 `.local/stage2/我的文章.txt`，记录真实来源链接。网页内容需要先自行取得正文，当前项目不会抓取链接。

先看请求：

```powershell
python '.\30-项目实践\02-模型API与文章整理\model_api.py' summarize --article '.\.local\stage2\我的文章.txt' --mode preview
```

检查实际发送的正文是否正确，提示要求是否清楚，输入是否在教学限制内。

## 第四步：准备好密钥后，生成真实草稿

按实践一设置会话环境变量，再运行：

```powershell
python '.\30-项目实践\02-模型API与文章整理\model_api.py' summarize --article '.\.local\stage2\我的文章.txt' --mode live --output '.\.local\stage2\article-live-01.md'
```

如果有原文链接，可增加 `--source-url` 后跟实际的单行 http(s) 链接。脚本直接保留你给的来源，不让模型补造。

输入正文会发送给 DeepSeek，可能产生账户费用。脚本先校验正常结束、非空内容、JSON 结构与原文依据片段，再保存“待核对”草稿。检查失败时不生成新笔记，也不会自动增加调用次数。

## 第五步：人工核对后入库

1. 摘要有没有漏掉或改变原文重点？
2. 原文中能找到依据，是否也确实支持对应观点？
3. 额外建议是否与原文事实分开？
4. 原文标题、作者、日期只在能确认时补充。
5. 整理到 `20-课程笔记`，保留来源和核对记录，再提交到 GitHub。

程序做的是短片段匹配，不会自动判断论证是否成立。“找到了这句话”与“这句话支持结论”需要分别检查。

## 第六步：修改与比较

- [ ] 在 `build_payload` 中只改一项整理要求，例如摘要句数。
- [ ] 对同一篇文章使用新的输出文件，再比较内容和用量。
- [ ] 用三篇熟悉文章填写 [评估记录模板](评估记录模板.md)。
- [ ] 记录一个失败或需要人工修正的案例，以及下一次要改什么。

真实模型可能空返回、截断或不符合字段要求；这些情况也是学习结果，应保留现象并按原因调整，而非直接把失败草稿作为知识入库。
