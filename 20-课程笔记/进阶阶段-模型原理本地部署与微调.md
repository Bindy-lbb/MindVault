## 环境与路线边界

当前只读检查未发现 Ollama 和 nvidia-smi 命令，因此默认安排 CPU 原理与数据练习；这不代替完整硬件诊断。真实训练脚本默认 CPU/FP32、小步数，仍需核实内存、磁盘、依赖支持和可接受耗时。没有为了完成资料整理而安装环境或下载权重。

[Datawhale self-llm](https://github.com/datawhalechina/self-llm)提供丰富的部署与微调教程，但其主线基于 Linux。Happy-LLM 第6章实践建议 Python 3.10/3.11 和较强 GPU 条件；完整教程的配置不是本机可直接照抄的保证。Windows 初学先用原生 Ollama 和本库 CPU 练习，真正跟进 GPU 教程时再确认操作系统与驱动。

Ollama 的 qwen2.5:0.5b 与 HF 的 Qwen/Qwen2.5-0.5B-Instruct 属于不同分发形式。二者不能直接互换缓存、适配器或量化文件。本库真实 LoRA 固定 HF revision，模型权重、环境、输出和训练数据扩展实验留在 `.local/`，不进入学习仓库。

## 我的完成标准

- [ ] 用自己的话说明注意力、掩码和下一 Token 损失的作用。
- [ ] 修改一组小矩阵输入，解释输出如何变化。
- [ ] 跑玩具 LoRA，比较训练/验证误差并重载适配器；明确它不是 LLM 微调。
- [ ] 若选本地推理，核对本地模型与云功能设置，保存实际输出和资源记录。
- [ ] 若选真实微调，先检查数据与模板、保存基座基准，再训练并单独评估测试集。
- [ ] 用[实验记录模板](../30-项目实践/06-模型原理本地部署与微调/进阶实验记录模板.md)填写实际结果、失败与限制，未运行的项目写未实测。
