## 这一阶段选择的技术栈

沿用 Markdown + Obsidian + GitHub；追加 Python 标准库做加载、来源记录和关键词基线，选修 Sentence Transformers 做本地 Embedding，真实生成复用第二阶段 DeepSeek HTTP 调用。JSON 索引与实验结果放 `.local/`。

选择原因：可以直接观察原文与片段；离线部分没有 API 费用；能在同一套题上比较检索方法；后续可以替换检索器、接入框架、向量数据库或网页界面。当前没有自动问答插件，也没有把全库内容发送给外部模型。

## 我的完成标准

- [ ] 能解释“切分 → 检索 → 生成”各自会出什么错。
- [ ] 亲自跑通离线建库、检索、摘录、评估，核对一条来源。
- [ ] 选择允许使用的 5–10 篇真实笔记，换资料后重跑。
- [ ] 做一个同义改写、一个跨笔记问题、一个无答案问题。
- [ ] 准备好账户后自行验证真实模型回答，人工检查每个结论与引用。
- [ ] 选修语义检索后记录模型/依赖版本与结果，不能用关键词实测代替向量实测。
- [ ] 修改资料并重建索引，用同一组题比较；记录一次失败与改进。

代码检查、模型实测与自己的学习完成度分开记录。当前检查边界见[运行检查记录](../30-项目实践/03-RAG知识库问答/运行检查记录.md)。
